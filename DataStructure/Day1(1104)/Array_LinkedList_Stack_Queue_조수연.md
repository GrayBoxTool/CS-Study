## 1. 개요 및 정의

자료구조는 데이터를 저장하고 관리하는 방식이다. 같은 데이터를 다뤄도 조회가 많은지, 중간 삽입이 많은지, 처리 순서가 중요한지에 따라 적합한 구조가 달라진다.

- **배열(Array)**: 같은 크기의 원소를 연속된 메모리 공간에 저장한다. 인덱스로 원소에 바로 접근할 수 있다.
- **연결 리스트(Linked List)**: 데이터와 다음 노드의 참조를 가진 노드들을 연결한다. 노드가 메모리에 연속으로 배치될 필요가 없다.
- **스택(Stack)**: 마지막에 넣은 원소를 먼저 꺼내는 LIFO 구조다.
- **큐(Queue)**: 먼저 넣은 원소를 먼저 꺼내는 FIFO 구조다.

배열과 연결 리스트는 저장 방식이고, 스택과 큐는 허용하는 연산과 처리 순서를 정의한 추상 자료형이다. 스택과 큐는 배열이나 연결 리스트로 구현할 수 있다.

## 2. 배열과 연결 리스트

### 2.1 배열: 인덱스로 바로 접근

```text
인덱스     0     1     2     3
배열     [10]  [20]  [30]  [40]
```

배열의 시작 주소와 원소 크기를 알면 다음 식으로 원소의 위치를 계산한다.

```text
원소 주소 = 시작 주소 + 인덱스 × 원소 크기
```

따라서 인덱스 접근은 O(1)이다. 하지만 정렬되지 않은 배열에서 특정 값을 찾는 연산은 최악의 경우 모든 원소를 확인하므로 O(n)이다. **인덱스로 접근하는 것과 값으로 검색하는 것은 다르다.**

중간에 원소를 삽입하거나 삭제하면서 순서를 유지하려면 뒤쪽 원소를 이동해야 하므로 O(n)이 걸린다. 연속된 메모리를 순서대로 읽기 쉬워 캐시 지역성이 좋은 편이다.

고정 크기 배열은 생성 후 크기를 바꿀 수 없다. 동적 배열은 용량이 부족하면 더 큰 저장 공간을 확보하고 기존 원소를 복사한다. 용량을 일정 비율로 늘리는 구현에서 끝에 추가하는 연산은 **분할 상환 O(1)**이지만, 재할당이 발생하는 한 번의 추가는 O(n)일 수 있다.

### 2.2 연결 리스트: 참조를 따라 이동

```text
head → [10 | next] → [20 | next] → [30 | null]
```

인덱스에 해당하는 노드에 도달하려면 앞에서부터 이동해야 하므로 접근은 O(n)이다. 반면 **단일 연결 리스트에서 삽입할 위치의 이전 노드를 이미 알고 있다면**, 참조만 바꿔 O(1)에 삽입할 수 있다.

예를 들어 A와 B 사이에 X를 넣을 때는 다음과 같이 연결한다.

```text
변경 전: A → B
변경 후: A → X → B

X.next = A.next
A.next = X
```

삭제도 이전 노드를 알고 있다면 연결을 바꿔 O(1)에 처리할 수 있다. 그러나 값이나 인덱스로 위치를 먼저 찾아야 한다면 탐색까지 포함해 O(n)이다. 이중 연결 리스트는 이전·다음 참조를 모두 저장하므로 대상 노드를 알고 있을 때 앞뒤 연결을 바꿔 삭제할 수 있다.

### 2.3 비교

| 연산·특징 | 동적 배열 | 단일 연결 리스트 |
| --- | --- | --- |
| 인덱스 접근 | O(1) | O(n) |
| 정렬되지 않은 데이터의 값 검색 | O(n) | O(n) |
| 중간 삽입·삭제 | 순서 유지 시 O(n) | 이전 노드를 알면 O(1), 위치 탐색 포함 시 O(n) |
| 끝에 추가 | 분할 상환 O(1), 재할당 시 O(n) | tail 참조가 있으면 O(1), 없으면 O(n) |
| 메모리 | 연속 공간, 여유 용량이 생길 수 있음 | 노드별 참조와 할당 비용이 추가됨 |
| 캐시 지역성 | 일반적으로 유리 | 일반적으로 불리 |

전체 저장 공간은 두 구조 모두 O(n)이지만 실제 메모리 사용량과 실행 속도는 구현에 따라 달라진다. 삽입이 많다는 이유만으로 연결 리스트가 항상 빠른 것은 아니다.

## 3. 스택과 큐

### 3.1 스택: LIFO

- `push`: 맨 위에 추가한다.
- `pop`: 맨 위 원소를 꺼낸다.
- `peek`: 맨 위 원소를 제거하지 않고 확인한다.

```text
push(A) → push(B) → push(C)
꺼내는 순서: C → B → A
```

**활용**: 함수 호출 관리, 괄호 검사, DFS, 실행 취소 기능.

괄호 검사에서는 여는 괄호를 스택에 넣고, 닫는 괄호가 나오면 맨 위의 여는 괄호와 짝이 맞는지 확인한다. 닫는 괄호가 나왔는데 스택이 비어 있거나, 끝까지 처리한 뒤 여는 괄호가 남아 있으면 올바른 괄호 문자열이 아니다.

배열의 끝이나 연결 리스트의 머리를 사용하면 효율적으로 구현할 수 있다. 동적 배열 구현의 `push`는 일반적으로 분할 상환 O(1)이고 재할당 시 O(n)이다.

### 3.2 큐: FIFO

- `enqueue`: 뒤쪽에 추가한다.
- `dequeue`: 앞쪽 원소를 꺼낸다.
- `peek`: 앞쪽 원소를 제거하지 않고 확인한다.

```text
enqueue(A) → enqueue(B) → enqueue(C)
꺼내는 순서: A → B → C
```

**활용**: BFS, 작업 대기열, 데이터 버퍼링.

배열의 첫 원소를 삭제할 때마다 나머지를 당기면 `dequeue`가 O(n)이 된다. 이를 피하려면 원형 배열에서 앞·뒤 인덱스를 관리하거나, head와 tail을 가진 연결 리스트를 사용한다. 고정 용량 원형 큐는 인덱스를 순환시켜 공간을 재사용하며, 가득 찼을 때의 처리 정책이 필요하다.

Python에서 큐가 필요하다면 다음처럼 양 끝 연산을 지원하는 `deque`를 사용할 수 있다.

```python
from collections import deque

queue = deque()
queue.append("A")
queue.append("B")

print(queue.popleft())  # A
print(queue.popleft())  # B
```

빈 스택이나 큐에서 꺼내는 경우도 처리해야 한다. 예를 들어 Python의 빈 `deque`에 `popleft()`를 호출하면 `IndexError`가 발생한다.

## 4. 실무·면접 핵심 질문

### Q1. 배열과 연결 리스트 중 어떤 것을 선택하나요?

인덱스 접근과 순차 순회가 많으면 배열이 유리하다. 연결 리스트는 노드 참조를 이미 가지고 있고 연결 변경이 자주 필요한 상황에서 고려한다. 탐색 비용, 추가 메모리, 캐시 효율까지 함께 판단해야 한다.

### Q2. 연결 리스트의 삽입·삭제는 항상 O(1)인가요?

아니다. 참조를 변경하는 연산만 O(1)이다. 단일 연결 리스트에서 이전 노드를 찾는 과정이 필요하면 전체 연산은 O(n)이다.

### Q3. DFS에는 스택, BFS에는 큐를 사용하는 이유는 무엇인가요?

DFS는 최근 발견한 경로를 먼저 깊게 탐색하므로 스택과 맞는다. 재귀 DFS는 호출 스택을 이용한다. BFS는 먼저 발견한 정점부터 처리해 시작점과 가까운 단계부터 탐색하므로 큐와 맞는다. 가중치가 없는 그래프에서 BFS는 간선 수 기준 최단 거리를 구할 수 있다.

### Q4. 큐를 배열로 구현할 때 주의할 점은 무엇인가요?

앞 원소를 삭제할 때마다 전체를 이동하지 않도록 해야 한다. 원형 배열을 사용한다면 빈 상태와 가득 찬 상태를 구분하고, 인덱스가 배열 끝을 넘어갈 때 순환시키는 처리가 필요하다.

## 5. 발표 핵심 요약

1. 배열은 연속 저장과 O(1) 인덱스 접근이 강점이고, 연결 리스트는 위치를 알고 있을 때 연결 변경이 쉽다.
2. 시간복잡도는 위치를 찾는 비용과 재할당 비용을 포함해 판단한다.
3. 스택은 LIFO, 큐는 FIFO이며 구현 방식에 따라 실제 연산 비용이 달라진다.
