## 1. 최단 경로와 MST는 무엇이 다를까?

### 1.1 최단 경로: 이동하는 비용을 최소화한다

학교 A에서 도서관 C까지 가는 상황이다. 도로별 이동 시간이 있으면 **한 경로에 포함된 가중치의 합**이 가장 작은 경로를 찾는다. 여기서 ‘짧다’는 직선거리가 아니라 우리가 가중치로 정한 시간·거리·요금이 작다는 뜻이다.

출발점을 하나 정해 다른 모든 정점까지 구하는 것이 단일 출발점 최단 경로다. 다익스트라와 벨만–포드가 여기에 해당한다. 플로이드–워셜은 모든 출발점과 도착점 조합을 한꺼번에 계산한다.

### 1.2 MST: 설치하는 연결의 총비용을 최소화한다

건물 A, B, C를 케이블로 모두 연결하려고 한다. A에서 C로 얼마나 빨리 이동하느냐보다 **설치한 케이블 전체 비용의 합**을 줄이는 것이 목표다.

신장 트리(spanning tree)는 원래 무방향 그래프의 모든 정점을 포함하면서, 연결되어 있고 사이클이 없는 부분 그래프다. 정점이 `V`개면 간선이 `V-1`개다. 그중 간선 가중치 합이 가장 작은 것이 최소 신장 트리(MST)다.

### 1.3 같은 그래프로 서로 다른 답 비교하기

아래는 **무방향** 그래프다. 선 양쪽으로 이동할 수 있다.

```text
       2
  A -------- B
   \        /
  3 \      / 2
     \    /
       C
```

| 질문 | 답 | 비용 |
|---|---|---:|
| A에서 C까지 가장 싸게 이동하려면? | A–C 직접 이동 | 3 |
| A, B, C를 가장 싸게 모두 연결하려면? | A–B와 B–C 설치 | 2+2=4 |
| 위 MST 안에서 A에서 C로 이동하면? | A–B–C | 4 |

**MST 안의 경로가 원래 그래프의 최단 경로라는 보장은 없다.** 반대로 A에서의 최단 경로들을 모은 트리도 MST라는 보장이 없다. 이 예에서 A의 최단 경로 트리는 A–B(2), A–C(3)로 총비용 5다.

| 구분 | 최단 경로 | MST |
|---|---|---|
| 핵심 질문 | 출발점에서 목적지까지 어떻게 싸게 이동할까? | 모든 정점을 어떻게 싸게 연결할까? |
| 최소화 대상 | 출발점→도착점 경로의 합 | 선택한 전체 간선의 합 |
| 방향 그래프 | 가능 | 이 자료의 일반 MST는 무방향 그래프 대상 |
| 출발점 | 단일 출발점 알고리즘은 필요 | 답의 목표에는 출발점이 없음; 프림은 작업 시작점만 선택 |
| 대표 결과 | 거리 배열/행렬과 경로 정보 | 간선 `V-1`개와 총비용 |
| 대표 모델 | 이동 시간, 전달 비용 | 케이블 설치 비용, 배관 연결 비용 |

발표할 때는 **‘이동’과 ‘설치’의 차이**를 먼저 말하면 이후 비교가 쉬워진다.

## 2. 다섯 알고리즘 한눈에 비교

### 2.1 특징과 결과

| 알고리즘 | 푸는 문제 | 핵심 생각 | 음수 간선 | 음수 사이클 |
|---|---|---|---|---|
| 다익스트라 | 한 출발점→모든 정점 | 누적 거리가 가장 작은 후보부터 처리 | 허용하지 않음 | 탐지용 알고리즘 아님 |
| 벨만–포드 | 한 출발점→모든 정점 | 모든 간선으로 거리를 반복 개선 | 허용 | 출발점에서 도달 가능한 음수 사이클 탐지 |
| 플로이드–워셜 | 모든 정점 쌍 | 경유지 후보를 하나씩 허용 | 허용 | 음수 대각선으로 존재 탐지 |
| 크루스칼 | MST | 전체 간선을 정렬하고 사이클 없이 선택 | 허용 | 최단 경로의 음수 사이클 문제와 관계없음 |
| 프림 | MST | 현재 트리와 바깥을 잇는 최소 간선 선택 | 허용 | 최단 경로의 음수 사이클 문제와 관계없음 |

벨만–포드/플로이드–워셜이 음수 사이클을 ‘처리한다’는 말은 그 사이클을 통과하는 유한한 최단 거리를 계산한다는 뜻이 아니다. 그런 거리가 존재하지 않는 상황을 알아낸다는 뜻이다. 자세한 영향 범위는 5~6장에서 구분한다.

### 2.1.1 다익스트라와 벨만–포드: 같은 질문, 다른 전제

둘 다 **출발점 하나에서 다른 모든 정점까지의 최단 거리**를 구한다. 차이는 음수 간선에 대한 전제와 거리를 처리하는 방식이다.

- **다익스트라: 음수 간선 불가, 0은 가능.** 가장 가까운 유효 후보를 꺼냈을 때 그 거리를 확정한다. 이후 이동 비용도 0 이상이면 더 먼 곳을 돌아와 더 싸게 만들 수 없기 때문이다.
- **벨만–포드: 음수 간선 가능.** 가까운 정점부터 확정하는 대신 모든 간선을 반복해서 완화한다. 뒤늦게 더 싼 경로가 발견되어도 다시 반영하므로 음수 간선이 있어도 계산할 수 있다. 대신 일반적으로 더 느리다.

같은 방향 그래프 `S→A(2), S→B(5), B→A(-10)`로 비교하자. A는 처음 2로 보이지만 실제 최단 거리는 S→B→A의 **−5**다. 다익스트라의 ‘A가 가까우니 2로 확정’이라는 논리는 깨진다. 벨만–포드는 이후 B→A를 확인하며 A의 기록을 −5로 고칠 수 있다. 본문 다익스트라 코드는 음수 입력을 거부한다.

**그렇다면 벨만–포드만 쓰면 되지 않을까?** 비음수 그래프에서는 다익스트라가 보통 더 효율적이다. 본문 기준으로 다익스트라는 힙을 이용하고, 벨만–포드는 최악에 모든 E개 간선을 V−1회 확인한다. 음수 허용이라는 장점과 반복 비용 사이에 차이가 있다.

### 2.1.2 플로이드–워셜: ‘음수 가능 여부’ 외에 질문의 범위가 다르다

플로이드–워셜도 **음수 간선을 허용**한다. 벨만–포드와의 주된 차이는 음수 여부가 아니라 **모든 출발점·도착점 쌍을 한 번의 실행으로 계산한다**는 점이다.

```text
다익스트라·벨만–포드에 출발점 A를 입력:
    [A→A, A→B, A→C]            → 거리 배열 한 줄

플로이드–워셜에 전체 그래프를 입력:
    [A→A, A→B, A→C]
    [B→A, B→B, B→C]            → 모든 출발점의 거리 행렬
    [C→A, C→B, C→C]
```

구현의 기준도 다르다. 다익스트라는 **가까운 정점 순서**, 벨만–포드는 **모든 간선 반복**, 플로이드–워셜은 **중간 정점 k를 하나씩 허용하며 모든 i→j 갱신**이다. 플로이드–워셜은 `i→k→j`가 기존 `i→j`보다 싼지 비교하는 동적 계획법이다.

| 비교 기준 | 다익스트라 | 벨만–포드 | 플로이드–워셜 |
|---|---|---|---|
| 한 번 실행한 결과 | 출발점 하나의 거리 배열 | 출발점 하나의 거리 배열 | 모든 출발점의 거리 행렬 |
| 음수 간선 | 불가, 0은 가능 | 가능 | 가능 |
| 계산 기준 | 최소 누적 거리 후보부터 | 모든 간선을 최대 V−1회 완화 | 경유지 k를 늘리며 모든 쌍 비교 |
| 대표 시간 복잡도 | 단순 그래프 힙 구현 O((V+E) log V) | O(VE) | O(V³) |
| 선택 상황 | 비음수, 한 출발점 | 음수 가능, 한 출발점 | 정점 수가 작고 모든 쌍 필요 |

**음수 간선 허용 ≠ 음수 사이클을 거치는 유한한 최단 거리 계산 가능.** 벨만–포드와 플로이드–워셜 모두, 출발점에서 음수 사이클에 도달하고 그곳에서 목적지로 갈 수 있으면 해당 거리의 유한한 최솟값은 없다. 본문 BF는 출발점에서 도달 가능한 음수 사이클을 찾으면 오류를 내고, FW는 그래프 어디에든 음수 사이클이 있으면 오류를 낸다.

모든 쌍이 필요해도 큰 비음수 희소 그래프라면 다익스트라를 출발점별로 반복하는 방법과 비교한다. **플로이드–워셜은 다익스트라의 ‘더 좋은 버전’이 아니라, 다른 계산 범위와 방식의 알고리즘이다.**

### 2.2 복잡도 빠른 비교

`V=정점 수`, `E=입력 간선 수`. 무방향 간선을 인접 리스트에 양방향으로 저장하면 항목은 `2E`개지만 빅오에서는 `O(E)`다. 아래 힙 구현은 기존 항목을 수정하지 않고 새 후보를 넣는 방식이다.

| 알고리즘 | 이 자료 코드의 시간 상한 | 입력 포함 공간 | 자주 보는 간단 표기 |
|---|---|---|---|
| 다익스트라 | `O(V + E log(E+1))` | `O(V+E)` | 단순 그래프에서 `O((V+E) log V)` |
| 벨만–포드 | `O(V + VE + E)` | `O(V+E)` | `O(VE)` |
| 플로이드–워셜 | `O(V³ + E)` | `O(V²+E)` | 시간 `O(V³)`, 행렬 공간 `O(V²)` |
| 크루스칼 | `O(V + E log(E+1))` | `O(V+E)` | `O(E log E)` |
| 프림 | `O(V + E log(E+1))` | `O(V+E)` | 연결 단순 그래프에서 `O(E log V)` |

단순 그래프는 같은 방향/두 정점 사이에 간선이 중복되지 않는 그래프다. 이때 `E=O(V²)`라서 `log E=O(log V)`로 쓸 수 있다. 중복 간선을 제한 없이 넣는다면 이 자료의 lazy 힙 크기는 `O(E)`이므로 `log(E+1)` 표기가 더 직접적이다. `+1`은 간선이 0개인 경우도 표현하려고 넣었다. 배열 초기화 `O(V)`도 생략하지 않았다.

벨만–포드의 보조 배열은 `O(V)`, 플로이드–워셜의 거리·경로 행렬은 `O(V²)`다. 입력을 저장하는 비용까지 센 표와 보조 공간만 센 표는 숫자가 다를 수 있다.

### 2.3 선택 흐름

```text
목적은?
├─ 모든 정점을 최소 총비용으로 연결
│  └─ 무방향 그래프인가?
│     ├─ 예: 간선 목록 중심 → 크루스칼
│     │      인접 리스트/한 트리 확장 중심 → 프림
│     └─ 아니오: 일반 MST의 범위 밖, 문제 조건 재확인
└─ 이동 비용 최소화
   ├─ 모든 간선 비용이 같은 양수 → BFS도 고려
   ├─ 한 출발점
   │  ├─ 모든 가중치 ≥ 0 → 다익스트라
   │  └─ 음수 간선 존재 → 벨만–포드, 음수 사이클 확인
   └─ 모든 출발점·도착점 쌍
      ├─ 정점 수가 작고 행렬을 쓸 수 있음 → 플로이드–워셜
      └─ 큰 희소 그래프, 가중치 ≥ 0 → 다익스트라 반복도 비교
```

이것은 다섯 알고리즘을 중심으로 한 선택 가이드다. DAG 최단 경로, 0–1 BFS, Johnson 등 다른 선택지도 있지만 본문에서는 다루지 않는다. ‘모든 쌍이면 무조건 플로이드’라고 외우지 않는다.

## 3. 구현 전 공통 준비

### 3.1 용어를 코드 변수로 연결하기

| 용어 | 쉬운 뜻 | 코드 표현 |
|---|---|---|
| 정점(vertex) | 장소·건물·상태 | `0, 1, ..., n-1` |
| 간선(edge) | 이동 또는 연결 가능 관계 | `(u, v, w)` |
| 가중치(weight) | 이동/설치에 드는 비용 | `w` |
| 방향 그래프 | `u→v`가 `v→u`를 보장하지 않음 | 한 방향만 저장 |
| 무방향 그래프 | 양방향 관계 | 인접 리스트에 양쪽 저장 |
| 경로 | 간선을 따라 이어지는 이동 | `[0, 2, 1]` |
| 사이클 | 돌아서 같은 정점으로 복귀 | `A→B→C→A` |
| 연결 요소 | 무방향 그래프에서 서로 이어진 정점 묶음 | Union-Find 집합 |
| 희소/밀집 | 간선이 적음/많음 | `E`가 `V`에 가깝거나 `V²`에 가까움 |

이 자료에서 가중치는 유한한 정수다. `inf`는 도달 불가를 표시하는 내부 값으로만 쓴다. 입력 정점 번호는 유효하다고 가정하며, `n>=1`, `0<=start<n`을 지킨다. 음수 간선 제한과 연결 여부 등 학습상 중요한 조건은 함수에서 확인한다.

### 3.2 같은 그래프를 세 방식으로 저장하기

```text
정점 A=0, B=1, C=2
방향 간선 A→B(4), A→C(1), C→B(2)

간선 목록: [(0, 1, 4), (0, 2, 1), (2, 1, 2)]
인접 리스트: [[(1, 4), (2, 1)], [], [(1, 2)]]
인접 행렬: [[0, 4, 1], [∞, 0, ∞], [∞, 2, 0]]
```

| 자료구조 | 무엇을 빨리 확인하나? | 쓰는 알고리즘 |
|---|---|---|
| 간선 목록 | 전체 간선을 차례로 확인 | 벨만–포드, 크루스칼 |
| 인접 리스트 | 현재 정점에서 나가는 간선 | 다익스트라, 프림 |
| 거리 행렬 | 모든 `i→j` 조합과 경유 비교 | 플로이드–워셜 |

행렬에서 간선 없음은 0이 아니라 `inf`다. 비용 0인 실제 간선이 있을 수 있기 때문이다. 자신에게 이동하지 않는 비용은 0이므로 대각선은 우선 0으로 둔다.

### 3.3 공통 인접 리스트 도우미

```python
from math import inf                       # 무한대: 아직 갈 수 없는 상태
import heapq                              # 최소 힙을 위한 표준 라이브러리


def make_adj(n, edges, directed=False):    # 정점 수, 간선 목록, 방향 여부
    graph = [[] for _ in range(n)]         # 정점마다 서로 다른 빈 리스트
    for u, v, w in edges:                  # 간선 하나를 출발·도착·비용으로 분해
        graph[u].append((v, w))            # u에서 v로 갈 수 있다고 기록
        if not directed:                  # 무방향이라면
            graph[v].append((u, w))        # 반대 방향도 기록
    return graph                          # 완성한 인접 리스트 반환
```

`[[]] * n`으로 만들면 같은 내부 리스트를 공유한다. 한 정점에 간선을 추가했는데 모든 정점에 추가되는 실수가 생긴다. `for _ in range(n)`은 서로 다른 리스트를 `n`개 만든다. `_`는 반복 횟수만 필요하고 반복 변수 자체는 쓰지 않는다는 관례다.

### 3.4 완화(relaxation): 더 싼 경로로 기록을 고친다

```text
현재 B까지 알고 있는 비용: dist[B] = 7
A까지 알고 있는 비용:     dist[A] = 3
A→B 간선 비용:           w = 2

A를 거쳐 가면 3+2=5 < 7
따라서 dist[B]를 5로 고친다.
```

핵심 식은 `dist[v] > dist[u] + w`다. 새 경로가 더 싸면 거리와 ‘직전에 어디서 왔는지’를 함께 바꾼다. 다익스트라와 벨만–포드 모두 이 동작을 쓴다. 차이는 **어떤 순서로, 얼마나 반복하느냐**다.

### 3.5 힙은 ‘가장 작은 후보를 먼저 꺼내는 상자’

`heapq.heappush(heap, (비용, 정점))`으로 후보를 넣고 `heapq.heappop(heap)`으로 가장 작은 튜플을 꺼낸다. 첫 값이 같으면 두 번째 값을 비교하므로 이 자료는 정점을 정수로 통일한다. 힙 내부 리스트 전체가 정렬된 것은 아니다. 꺼낼 때마다 최솟값을 얻는다. API의 동작은 [Python 공식 heapq 문서](https://docs.python.org/3/library/heapq.html)에서 확인할 수 있다.

다익스트라의 힙 첫 값은 **출발점부터의 누적 거리**, 프림의 힙 첫 값은 **새 정점을 연결하는 간선 하나의 가중치**다. 생김새가 비슷해도 목적이 다르다.

### 3.6 부모 배열로 실제 경로 복원하기

`parent[v]=u`는 현재 최선 경로에서 `v` 바로 앞 정점이 `u`라는 뜻이다. 목적지에서 부모를 거슬러 올라간 뒤 뒤집는다.

```python
def restore_path(parent, start, target):   # 성공적으로 계산한 부모 배열만 입력
    path = []                             # 목적지부터 거꾸로 모을 경로
    cur = target                          # 목적지에서 시작
    while cur != -1:                      # 부모가 없는 지점에 이를 때까지
        path.append(cur)                  # 현재 정점을 기록
        if cur == start:                  # 출발점에 도달했다면
            return path[::-1]             # 역순을 뒤집어 출발→도착으로 반환
        cur = parent[cur]                 # 직전 정점으로 이동
    return []                             # 출발점으로 이어지지 않으면 도달 불가
```

`start==target`이면 `[start]`를 돌려준다. 음수 사이클을 탐지한 실패 결과의 부모 배열에는 쓰지 않는다. 아래 벨만–포드는 실패 시 예외를 발생시켜 이 경우를 막는다.

## 4. 다익스트라: 현재 가장 가까운 후보부터 확장하기

### 4.1 직관과 전제

출발점에서 가까운 곳의 경로부터 완성한다. 지금 가장 작은 누적 거리가 3인데 아직 처리하지 않은 후보가 전부 5 이상이고 이후 간선 비용도 음수가 아니라면, 나중에 5 이상인 곳을 돌아서 비용 3을 더 줄일 수 없다.

이것이 **가장 작은 유효 후보를 꺼냈을 때 그 거리를 확정할 수 있는 이유**다. 비용 0인 간선은 괜찮다. 음수 간선은 이 논리를 깨므로 이 자료의 구현에서는 입력 단계에서 거부한다.

### 4.2 손으로 따라가기

다음은 **무방향** 그래프다. 이후 크루스칼·프림에서도 같은 그래프를 사용한다.

| 간선 | 비용 | 간선 | 비용 |
|---|---:|---|---:|
| A–C | 1 | C–D | 8 |
| B–C | 2 | C–E | 10 |
| D–E | 2 | B–D | 5 |
| A–B | 4 | | |

8~9장 MST 예제에서도 이 그래프를 그대로 사용한다.

정점 번호는 A=0, B=1, C=2, D=3, E=4다. 출발점은 A다.

| 유효하게 꺼낸 정점 | 거리 `[A,B,C,D,E]` | 이번에 바뀐 기록 |
|---|---|---|
| 초기 | `[0,∞,∞,∞,∞]` | A만 0 |
| A(0) | `[0,4,1,∞,∞]` | B=4, C=1 |
| C(1) | `[0,3,1,9,11]` | B=1+2=3, D=1+8=9, E=1+10=11 |
| B(3) | `[0,3,1,8,11]` | D=3+5=8 |
| D(8) | `[0,3,1,8,10]` | E=8+2=10 |
| E(10) | `[0,3,1,8,10]` | 없음 |

여기에는 최신 후보만 적었다. 실제 힙에서는 과거 후보 B(4), D(9), E(11)도 꺼내지만 이미 더 짧은 값이 있으므로 건너뛴다.

```text
A→E 최단 경로: A→C→B→D→E
거리: 1+2+5+2 = 10
```

### 4.3 Python 구현: 코드 옆 짧은 주석

```python
def dijkstra(n, graph, start):                    # 정점 수, 인접 리스트, 출발점
    for neighbors in graph:                     # 모든 정점의 간선 목록을 검사
        for v, w in neighbors:                  # 목적지와 간선 비용을 꺼냄
            if w < 0:                           # 음수 간선이 하나라도 있으면
                raise ValueError("다익스트라는 음수 간선을 허용하지 않습니다.")  
    dist = [inf] * n                            # 아직 모르는 거리는 무한대
    parent = [-1] * n                           # 직전 정점은 아직 없음
    dist[start] = 0                             # 출발점까지는 이동 비용 0
    heap = [(0, start)]                         # (누적 거리, 정점) 후보를 넣음
    while heap:                                 # 처리할 후보가 남아 있는 동안
        cur_dist, u = heapq.heappop(heap)        # 가장 작은 누적 거리 후보
        if cur_dist != dist[u]:                 # 최신 기록과 다르면 오래된 후보
            continue                            # 이 후보로는 간선을 검사하지 않음
        for v, w in graph[u]:                   # u에서 나갈 수 있는 간선마다
            candidate = cur_dist + w            # 출발→u→v의 전체 이동 비용
            if candidate < dist[v]:             # 기존 경로보다 짧을 때만
                dist[v] = candidate             # 거리 기록 갱신
                parent[v] = u                   # 경로 복원을 위해 직전 정점 기록
                heapq.heappush(heap, (candidate, v))  # 새 경로를 처리 후보로 추가
    return dist, parent                         # 거리와 경로 정보를 함께 반환
```


`visited` 배열이 없어도 된다. 이 구현은 **최신 거리와 일치하는 후보만 처리**하고, 비음수 가중치 아래에서는 그렇게 꺼낸 정점의 거리가 이후 더 작아지지 않는다.

### 4.4 실행 가능한 예제

```python
base_edges = [
    (0, 1, 4), (0, 2, 1), (1, 2, 2),
    (1, 3, 5), (2, 3, 8), (2, 4, 10), (3, 4, 2),
]
base_graph = make_adj(5, base_edges, directed=False)
dist_d, parent_d = dijkstra(5, base_graph, 0)
print(dist_d)
print(restore_path(parent_d, 0, 4))
```

```text
[0, 3, 1, 8, 10]
[0, 2, 1, 3, 4]
```

출력의 `[0,2,1,3,4]`는 정점 번호를 나열한 경로다. 그 숫자들의 합이 거리가 아니다. 실제 간선 가중치 `1+2+5+2`를 더해야 10이 된다.

### 4.5 왜 음수 간선에서 확정 논리가 깨질까?

```text
S→A: 2, S→B: 5, B→A: -10
```

A(2)를 먼저 꺼내면 기존 논리상 확정하고 싶다. 하지만 B를 거치면 A까지 `5-10=-5`가 된다. 따라서 ‘한 번 꺼내면 확정’이라는 증명과 보통의 시간 상한을 그대로 사용할 수 없다.

힙에 재삽입하는 코드가 일부 음수 예제에서 우연히 정답을 내기도 한다. 그것을 음수 허용 다익스트라로 일반화하면 안 된다. 특히 목적지를 처음 꺼냈을 때 종료하거나 방문 완료 정점을 재처리하지 않는 변형은 위 예제에서 틀린다. **음수 간선이 있으면 이 가이드에서는 벨만–포드를 선택한다.**

### 4.6 실제 활용: 장소 이름을 코드로 넣기

학습용 도보 지도라고 생각하자. 시간 단위는 분이다.

```python
places = ["기숙사", "도서관", "식당", "강의실", "체육관"]
place_id = {name: i for i, name in enumerate(places)}   # 이름→정수 번호
walkways = [                                         # 실제 입력에 해당하는 원자료
    ("기숙사", "도서관", 4), ("기숙사", "식당", 1),
    ("도서관", "식당", 2), ("도서관", "강의실", 5),
    ("식당", "강의실", 8), ("식당", "체육관", 10),
    ("강의실", "체육관", 2),
]
walk_edges = [(place_id[a], place_id[b], minutes)
              for a, b, minutes in walkways]         # 이름을 번호로 변환
walk_graph = make_adj(len(places), walk_edges, directed=False)
walk_dist, walk_parent = dijkstra(len(places), walk_graph, place_id["기숙사"])
walk_route = restore_path(walk_parent, place_id["기숙사"], place_id["체육관"])
print(walk_dist[place_id["체육관"]])
print(" → ".join(places[i] for i in walk_route))        # 정수 경로를 장소명으로 복원
```

```text
10
기숙사 → 식당 → 도서관 → 강의실 → 체육관
```

`enumerate`는 리스트 항목에 0부터 번호를 붙인다. 딕셔너리의 `place_id["식당"]`은 2다. 리스트 컴프리헨션은 원자료를 `(출발 번호, 도착 번호, 시간)`으로 바꾼다. 마지막 `join`은 경로의 장소명 사이에 화살표를 끼워 문자열로 만든다.

현실의 내비게이션을 이 코드와 동일시하지는 않는다. 이 모델은 비용이 고정되어 있고 경로 비용을 간선별로 더할 수 있다고 가정한다. 출발 시각에 따라 소요 시간이 바뀌거나 회전 제한이 있으면 상태와 가중치 모델을 확장해야 한다.

### 4.7 복잡도와 구현 실수

배열 초기화 `O(V)`, 전체 음수 검사 `O(V+E)`, 간선 검사 `O(E)`, 개선 때마다 힙 삽입이 발생한다. 힙에 예전 후보까지 쌓이므로 크기는 최악 `O(E)`이고 전체 시간은 `O(V+E log(E+1))`, 입력을 포함한 공간은 `O(V+E)`다.

- 힙에 `(정점, 거리)`를 넣으면 정점 번호가 우선된다. 반드시 `(거리, 정점)`이다.
- `candidate=w`로 쓰면 출발점부터의 거리를 버린다. `cur_dist+w`다.
- ‘가중치가 전부 양수’보다 정확한 조건은 ‘전부 **0 이상**’이다.
- 목표 하나만 필요할 때 조기 종료하려면 **오래된 후보를 건너뛴 뒤**, 목표의 최신 후보를 꺼낸 시점이어야 한다. 이 본문 함수는 전체 거리 배열을 완성한다.
- 도달 불가 정점의 거리는 `inf`, 복원 경로는 `[]`다.

## 5. 벨만–포드: 음수 간선이 있어도 반복해서 고치기

### 5.1 왜 새로운 알고리즘이 필요할까?

다익스트라는 음수 간선이 없다는 조건을 이용해서, 현재 가장 가까운 정점의 거리를 확정한다. 그런데 뒤쪽에 음수 간선이 있다면 나중에 더 싸게 도착하는 방법을 발견할 수 있다.

벨만–포드는 거리를 일찍 확정하지 않는다. **모든 간선을 여러 번 확인하며, 더 싼 경로를 발견할 때마다 거리를 고친다.**

핵심은 앞에서 배운 완화다.

```text
u까지의 비용 + u → v의 비용 < 현재 v까지의 비용
→ v까지의 비용을 새 값으로 교체한다.
```

음수 간선은 “그 구간을 이용하면 총비용이 줄어든다”는 뜻이다. 거리나 소요 시간에는 대개 어울리지 않지만, 할인·보상·손익 같은 값에는 사용할 수 있다.

### 5.2 음수 간선과 음수 사이클은 다르다

다음은 음수 간선이 있지만 사이클은 없는 그래프다.

```text
A → B : 4
A → C : 5
B → C : -2
C → D : 3
```

A에서 C로 바로 가면 5지만, B를 거치면 `4 + (-2) = 2`다. 따라서 최단 경로는 정상적으로 존재한다.

반면 다음 사이클의 비용 합은 음수다.

```text
B → C : -2
C → B :  1
사이클 한 바퀴 비용 = -1
```

이 사이클에 도달할 수 있고 같은 길을 반복해서 이용할 수 있다면, 한 바퀴 돌 때마다 비용이 1씩 줄어든다. 이때 사이클과 그 뒤로 갈 수 있는 정점들의 최단 거리는 유한한 값으로 정해지지 않는다.

> **정확한 조건:** 출발점에서 도달 가능한 음수 사이클이 있어도 모든 정점의 최단 거리가 사라지는 것은 아니다. 그 사이클에서 도달할 수 있는 정점들이 영향을 받는다. 아래 입문용 코드는 출발점에서 도달 가능한 음수 사이클을 하나라도 찾으면 `ValueError`를 발생시키고 전체 결과를 반환하지 않는다.

방향 없는 음수 간선을 양방향 간선 두 개로 저장하면 왕복으로 비용을 계속 줄일 수 있다. 일반적인 최단 경로 문제에서는 경로 반복을 허용하므로 주의한다.

### 5.3 왜 최대 V−1번 반복할까?

음수 사이클의 영향을 받지 않는 최단 경로는 정점을 중복하지 않는 경로로 고를 수 있다. 정점이 V개면 이런 경로의 간선 수는 최대 V−1개다.

모든 간선을 한 번 확인할 때마다, 적어도 간선 수가 하나 더 긴 경로까지 반영할 수 있다. 그래서 최대 V−1번 모든 간선을 확인하면 충분하다.

다만 아래 코드는 같은 거리 배열을 즉시 수정한다. 간선의 확인 순서가 좋으면 한 번의 반복에서 여러 구간이 연이어 반영될 수 있다.

**“1회 반복이면 정확히 간선 1개짜리 경로만 반영된다”는 설명은 이 구현에 맞지 않는다.** 정확히 간선 수를 제한하는 동적 계획법을 구현하려면 이전 배열을 따로 복사해야 한다.

### 5.4 손으로 따라가기: 일부러 역순으로 확인하기

정점 번호는 `A=0, B=1, C=2, D=3`으로 정한다. 간선은 다음 순서로 저장한다.

```python
edges = [
    (2, 3, 3),    # C → D, 비용 3
    (1, 2, -2),   # B → C, 비용 -2
    (0, 2, 5),    # A → C, 비용 5
    (0, 1, 4),    # A → B, 비용 4
]
```

`∞`는 아직 도달 방법을 찾지 못했다는 뜻이다. 출발점 A의 거리만 0으로 시작한다.

| 시점 | A | B | C | D | 변화 |
|---|---:|---:|---:|---:|---|
| 초기 | 0 | ∞ | ∞ | ∞ | A에서 출발 |
| 1회 전체 확인 뒤 | 0 | 4 | 5 | ∞ | A→C, A→B가 반영됨 |
| 2회 전체 확인 뒤 | 0 | 4 | 2 | 8 | C→D가 먼저 8을 만들고, B→C가 C를 2로 고침 |
| 3회 전체 확인 뒤 | 0 | 4 | 2 | 5 | 새 C 거리 2를 이용해서 D를 5로 고침 |

2회차가 헷갈리기 쉽다. 간선별로 풀어 보면 다음과 같다.

1. C→D 확인: 그 순간 C의 거리는 5이므로 D를 `5+3=8`로 바꾼다.
2. B→C 확인: C를 `4−2=2`로 바꾼다.
3. A→C 확인: 후보 5는 현재 2보다 크므로 무시한다.
4. A→B 확인: 후보 4와 현재 4가 같으므로 무시한다.
5. C→D는 이미 지나갔으므로, D의 추가 개선은 다음 회차에 일어난다.

최종 경로는 `A → B → C → D`, 비용은 `4−2+3=5`다.

### 5.5 음수 사이클은 한 번 더 확인해서 찾는다

V−1번 반복한 뒤에도 완화할 수 있는 간선이 남아 있다면, 출발점에서 도달 가능한 음수 사이클이 있다.

이때 `dist[u] != INF` 조건이 중요하다. 출발점에서 갈 수 없는 구역의 음수 사이클은 이번 출발점의 결과에 영향을 주지 않는다.

중간에 모든 간선을 확인했는데 값이 하나도 바뀌지 않았다면 더 반복할 필요가 없다. 이것이 `changed`와 조기 종료의 역할이다.

### 5.6 Python 구현

입력은 방향 그래프의 간선 목록 `(출발, 도착, 비용)`이다. 정점 번호는 `0`부터 `n-1`까지이며, 번호와 출발점은 올바르다고 가정한다.

`parent[v]`에는 v 직전에 방문한 정점을 저장한다. 음수 사이클이 없을 때 경로를 복원하는 데 쓸 수 있다.

```python
def bellman_ford(n, edges, start):                         # 정점 수, 간선 목록, 출발점을 받는다
    INF = float("inf")                                   # 아직 갈 수 없는 상태를 무한대로 표현한다
    dist = [INF] * n                                      # 모든 정점까지의 거리를 무한대로 시작한다
    parent = [-1] * n                                     # 경로 복원에 사용할 이전 정점을 비워 둔다
    dist[start] = 0                                       # 출발점에서 출발점까지의 비용은 0이다
    for _ in range(n - 1):                                # 전체 간선 확인을 최대 V−1번 반복한다
        changed = False                                  # 이번 회차에 거리 수정이 있었는지 기록한다
        for u, v, weight in edges:                        # 모든 방향 간선을 하나씩 꺼낸다
            if dist[u] == INF:                            # u에 도달할 수 없다면 u에서 출발하는 경로도 아직 사용할 수 없다
                continue                                 # 이번 간선을 건너뛰고 다음 간선을 확인한다
            candidate = dist[u] + weight                  # u를 거쳐 v에 도착하는 후보 비용을 계산한다
            if candidate < dist[v]:                      # 기존 비용보다 작은 경우에만 완화한다
                dist[v] = candidate                      # v의 최단 거리 후보를 새 비용으로 교체한다
                parent[v] = u                            # 새 경로에서 v 직전 정점은 u다
                changed = True                           # 이번 회차에 변경이 있었음을 표시한다
        if not changed:                                  # 전체 간선을 확인해도 변하지 않았는지 확인한다
            break                                        # 변하지 않았다면 반복을 끝낸다
    for u, v, weight in edges:                            # 음수 사이클 검사를 위해 간선을 한 번 더 확인한다
        if dist[u] != INF and dist[u] + weight < dist[v]:  # 출발점에서 도달 가능한 간선에서 추가 개선이 있는지 확인한다
            raise ValueError("출발점에서 도달 가능한 음수 사이클이 있습니다.")  # 음수 사이클이 발견되면 예외를 발생시키고 거리와 경로 정보 모두 반환하지 않는다
    return dist, parent                                  # 음수 사이클이 없다면 거리 배열과 이전 정점 배열을 반환한다
if __name__ == "__main__":
    edges = [(2, 3, 3), (1, 2, -2), (0, 2, 5), (0, 1, 4)]
    try:
        dist, parent = bellman_ford(4, edges, 0)
    except ValueError as error:
        print(error)
    else:
        print(dist)
        print(parent)
```

실행 결과:

```text
[0, 4, 2, 5]
[-1, 0, 1, 2]
```

성공적으로 계산한 부모 배열은 3.6절의 공용 `restore_path`에 그대로 넣을 수 있다. 다음 예제는 위 정상 그래프의 계산 결과를 사용한다.

```python
path = restore_path(parent, 0, 3)  # 부모 배열을 거슬러 A에서 D까지의 경로 복원
print(path)                       # [0, 1, 2, 3]
```


`try` 안에서 함수를 호출하고 `except ValueError`에서 실패를 처리한다. 실패한 호출에서는 거리나 부모 배열을 새로 받지 못하므로, 경로 복원과 거리 출력은 성공한 경우에만 실행한다.

### 5.7 실생활 상황을 입력 데이터로 바꾸기

**상황:** 이동할 때 요금을 내기도 하고, 특정 구간에서 보상을 받기도 한다. 보상을 포함한 순비용을 최소화하고 싶다.

| 현실의 정보 | 코드 표현 |
|---|---|
| 출발지·정류장·목적지 | 정점 |
| 한 방향으로 이동 가능한 구간 | 방향 간선 |
| 요금에서 해당 구간의 반복 가능한 보상을 뺀 값 | 가중치 |
| 처음 출발하는 장소 | `start` |
| 목적지까지 최소 순비용 | `dist[목적지 번호]` |

다음 코드는 위 함수 아래에 붙여 실행할 수 있다.

```python
places = ["출발지", "환승역", "보상지점", "목적지"]
index = {name: i for i, name in enumerate(places)}

routes = [
    ("보상지점", "목적지", 3),
    ("환승역", "보상지점", -2),
    ("출발지", "보상지점", 5),
    ("출발지", "환승역", 4),
]
edges = [(index[a], index[b], cost) for a, b, cost in routes]
try:
    dist, parent = bellman_ford(len(places), edges, index["출발지"])
except ValueError:
    print("반복 이동으로 순비용을 계속 줄일 수 있는 구간이 있습니다.")
else:
    if dist[index["목적지"]] == float("inf"):
        print("목적지에 도달할 수 없습니다.")
    else:
        print("최소 순비용:", dist[index["목적지"]])  # 최소 순비용: 5
        path = restore_path(parent, index["출발지"], index["목적지"])
        print(" → ".join(places[v] for v in path))  # 출발지 → 환승역 → 보상지점 → 목적지
```

이름을 번호로 바꾸는 이유는 알고리즘이 거리와 부모 정보를 배열에 저장하기 때문이다. `index["환승역"]`은 사람이 쓰는 이름과 배열 번호를 연결한다.

**모델링에서 꼭 확인할 점:** “쿠폰은 한 번만 사용 가능”이라면 같은 구간을 지날 때마다 음수 비용을 적용하면 안 된다. 이 경우 정점을 `(장소, 쿠폰 사용 여부)`로 늘려야 한다. 알고리즘을 바꾸기 전에 입력 모델이 현실의 규칙을 담았는지 확인해야 한다.

### 5.8 복잡도와 실수

- 시간: 일반적으로 **O(VE)**라고 표현한다. 이 코드의 초기화와 추가 검사까지 포함하면 `O(V + (V−1)E + E)`이며, 느슨한 상한은 `O(V+E+VE)`다.
- 추가 공간: 거리와 부모 배열이 **O(V)**다. 입력 간선 목록까지 포함하면 **O(V+E)**다.
- 조기 종료하면 빠를 수 있지만, 최악의 시간 복잡도는 그대로다.
- 출발점에서 갈 수 없는 정점의 거리는 `inf`다. 큰 수나 정상 거리처럼 출력하지 않는다.
- 음수 사이클을 발견하면 `ValueError`가 발생한다. 예외를 처리한 뒤 과거 호출의 거리 배열을 이번 결과처럼 사용하지 않는다.
- `n=1`이면 거리 갱신 반복은 0번이다. 마지막 간선 검사에서 출발점의 음수 자기 루프도 찾아낸다.

그래프 전체의 음수 사이클 존재 여부만 검사하려면, 이 코드의 거리 초기화를 모든 정점에 대해 `dist = [0] * n`으로 바꾸어 모든 구역을 처음부터 도달 가능하게 취급할 수 있다. 이는 새 슈퍼소스 정점을 추가하고 모든 기존 정점으로 비용 0인 간선을 연결해 벨만–포드를 실행하는 방법과 같은 효과이며, 원래 출발점의 최단 거리를 구하는 호출과는 별도로 사용한다.

발표 한 문장: **“벨만–포드는 모든 간선을 최대 V−1번 완화하고, 한 번 더 개선되는지 확인해서 출발점에서 도달 가능한 음수 사이클을 찾습니다.”**

## 6. 플로이드–워셜: 모든 출발점과 도착점을 한꺼번에

### 6.1 거리 배열이 표로 커진다

다익스트라와 벨만–포드는 출발점 하나의 거리 배열 `dist[v]`를 만든다.

플로이드–워셜은 **모든 정점 쌍**의 거리표 `dist[i][j]`를 만든다. `dist[i][j]`는 i에서 j로 가는 최소 비용이다.

| 알고리즘 | 질문 | 결과 형태 |
|---|---|---|
| 다익스트라·벨만–포드 | “A에서 각 장소까지 얼마인가?” | 1차원 배열 |
| 플로이드–워셜 | “어느 장소에서 어느 장소로 가든 얼마인가?” | 2차원 배열 |

핵심 질문은 하나다.

> i에서 j로 갈 때, **k를 거쳐 가면 더 싸질까?**

```text
기존 i → j 비용
vs.
i → k 비용 + k → j 비용
```

점화식은 다음과 같다.

```text
dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
```

여기서 k는 “반드시 한 번만 거치는 정점”이 아니다. 현재까지 허용한 중간 정점 집합에 k를 추가한다는 뜻이다. i→k와 k→j 자체가 이미 여러 간선을 포함할 수 있다.

### 6.2 왜 k 반복문이 가장 바깥에 있을까?

처음에는 직접 연결된 길과 자기 자신에게 가는 비용만 안다.

1. 중간 정점으로 A만 허용해서 모든 쌍을 갱신한다.
2. 중간 정점으로 A, B를 허용해서 모든 쌍을 갱신한다.
3. 중간 정점으로 A, B, C를 허용해서 모든 쌍을 갱신한다.
4. 이런 방식으로 허용하는 중간 정점 집합을 늘린다.

이 단계 구조 때문에 `for k`가 가장 바깥이다. 안쪽 i와 j의 순서는 서로 바꿔도 되지만, k를 안으로 옮긴 단 한 번의 3중 반복은 일반적으로 정답을 보장하지 않는다.

음수 사이클이 없으면 자기 자신까지의 비용은 0이다. 따라서 같은 표를 수정하면서 진행해도 이 단계별 의미가 유지된다.

### 6.3 손으로 따라가기: 표 세 번 고치기

`A=0, B=1, C=2`인 방향 그래프를 사용한다.

```text
A → B :  4
A → C : 10
B → C : -2
C → A :  5
```

이 그래프의 `A→B→C→A` 사이클 비용은 `4−2+5=7`이다. 음수 간선은 있지만 음수 사이클은 없다.

#### 초기 표

자기 자신은 0, 직접 간선이 있으면 그 비용, 없으면 ∞다.

| 출발 \ 도착 | A | B | C |
|---|---:|---:|---:|
| A | 0 | 4 | 10 |
| B | ∞ | 0 | -2 |
| C | 5 | ∞ | 0 |

#### 1단계: k=A

C에서 B로 가는 길을 새로 찾는다.

```text
C → A → B = 5 + 4 = 9
기존 ∞보다 작으므로 C→B를 9로 바꾼다.
```

| 출발 \ 도착 | A | B | C |
|---|---:|---:|---:|
| A | 0 | 4 | 10 |
| B | ∞ | 0 | -2 |
| C | 5 | 9 | 0 |

#### 2단계: k=B

A에서 C로 직접 가는 것보다 B를 거치는 것이 싸다.

```text
A → B → C = 4 + (-2) = 2
기존 10보다 작으므로 A→C를 2로 바꾼다.
```

| 출발 \ 도착 | A | B | C |
|---|---:|---:|---:|
| A | 0 | 4 | 2 |
| B | ∞ | 0 | -2 |
| C | 5 | 9 | 0 |

#### 3단계: k=C

B에서 A로 가는 길을 새로 찾는다.

```text
B → C → A = -2 + 5 = 3
기존 ∞보다 작으므로 B→A를 3으로 바꾼다.
```

| 출발 \ 도착 | A | B | C |
|---|---:|---:|---:|
| A | 0 | 4 | 2 |
| B | 3 | 0 | -2 |
| C | 5 | 9 | 0 |

이 표가 최종 결과다. 예를 들어 A→C의 최단 경로는 `A→B→C`이며 비용은 2다.

### 6.4 Python 구현: 거리와 실제 경로를 함께 구하기

`next_hop[i][j]`는 i에서 j로 최단 경로를 따라갈 때 **i 다음에 방문할 정점**이다. 벨만–포드의 `parent[v]`가 “직전 정점”인 것과 방향이 다르다.

```python
def floyd_warshall(n, edges, directed=True):              # 정점 수, 간선 목록, 방향 그래프 여부를 받는다
    INF = float("inf")                                   # 도달할 수 없는 상태를 무한대로 표시한다
    dist = [[INF] * n for _ in range(n)]                   # 서로 독립적인 행을 가진 n×n 거리표를 만든다
    next_hop = [[None] * n for _ in range(n)]              # 각 출발·도착 쌍의 다음 방문 정점을 저장할 표를 만든다
    for i in range(n):                                    # 자기 자신으로 가는 값을 초기화하기 위해 정점을 순회한다
        dist[i][i] = 0                                    # 아무 간선도 이용하지 않는 비용을 0으로 둔다
        next_hop[i][i] = i                                # 자기 자신으로 가는 경로의 다음 정점은 자기 자신이다
    for u, v, weight in edges:                            # 직접 연결된 간선을 읽는다
        if weight < dist[u][v]:                           # 같은 방향의 간선이 여러 개면 더 싼 것만 사용한다
            dist[u][v] = weight                           # 직접 간선 비용을 거리표에 기록한다
            next_hop[u][v] = v                            # 직접 가는 경로의 다음 정점은 도착점이다
        if not directed and weight < dist[v][u]:          # 무방향 그래프로 요청했다면 반대 방향도 확인한다
            dist[v][u] = weight                           # 반대 방향 비용도 기록한다
            next_hop[v][u] = u                            # 반대 방향 경로의 다음 정점도 기록한다
    for k in range(n):                                    # 새로 허용할 중간 정점 k를 정한다
        for i in range(n):                                # 출발 정점 i를 정한다
            if dist[i][k] == INF:                         # i에서 k로 갈 수 있는지 확인한다
                continue                                 # 갈 수 없으면 해당 i의 갱신을 생략한다
            for j in range(n):                            # 도착 정점 j를 정한다
                if dist[k][j] == INF:                     # k에서 j로 갈 수 있는지 확인한다
                    continue                             # 갈 수 없으면 해당 j를 생략한다
                candidate = dist[i][k] + dist[k][j]        # k를 경유하는 후보 비용을 구한다
                if candidate < dist[i][j]:                # 기존 i→j 비용보다 싼지 확인한다
                    dist[i][j] = candidate                # 더 싸면 거리표를 갱신한다
                    next_hop[i][j] = next_hop[i][k]        # 새 경로의 첫 이동은 i→k 경로의 첫 이동과 같다
    if any(dist[v][v] < 0 for v in range(n)):              # 자기 자신에게 돌아오는 음수 비용이 있는지 검사한다
        raise ValueError("그래프에 음수 사이클이 있습니다.") # 이 구현은 그래프 어디에든 음수 사이클이 있으면 결과 반환을 중단한다
    return dist, next_hop                                 # 거리표와 다음 방문 정점 표를 반환한다
def reconstruct_floyd_path(dist, next_hop, start, end):    # 음수 사이클 없이 성공적으로 완료된 같은 실행의 거리표와 다음 정점 표, 시작·도착 번호를 받는다
    n = len(dist)                                         # 거리표에서 정점 수를 읽는다
    if not (0 <= start < n and 0 <= end < n):              # 시작과 도착 번호가 유효한 범위인지 검사한다
        raise IndexError("정점 번호가 범위를 벗어났습니다.") # 잘못된 번호로 배열을 읽지 않도록 오류를 낸다
    if next_hop[start][end] is None:                       # 도착점으로 가는 다음 정점이 존재하는지 확인한다
        return []                                        # 도달할 수 없으면 빈 목록을 반환한다
    path = [start]                                       # 경로에 시작 정점을 먼저 넣는다
    current = start                                      # 현재 위치를 시작 정점으로 둔다
    while current != end:                                # 도착하기 전까지 다음 정점으로 이동한다
        current = next_hop[current][end]                  # 현재 위치에서 목적지로 가기 위한 첫 이동을 읽는다
        if current is None:                              # 잘못된 표가 전달되어 이동 정보가 끊겼는지 확인한다
            raise ValueError("경로 정보가 올바르지 않습니다.") # 경로 정보가 일관되지 않으면 오류를 낸다
        path.append(current)                             # 새 위치를 경로에 추가한다
        if len(path) > n:                                 # 정상적으로 계산된 최단 경로는 정점 반복 없이 고를 수 있으므로 길이가 n을 넘는지 확인한다
            raise ValueError("경로 정보에 순환이 있습니다.") # 손상된 다음 정점 정보 때문에 무한 반복하지 않도록 중단한다
    return path                                          # 시작부터 도착까지의 정점 번호 목록을 반환한다
if __name__ == "__main__":
    edges = [(0, 1, 4), (0, 2, 10), (1, 2, -2), (2, 0, 5)]
    dist, next_hop = floyd_warshall(3, edges)
    for row in dist:
        print(row)
    print(reconstruct_floyd_path(dist, next_hop, 0, 2))
```

실행 결과:

```text
[0, 4, 2]
[3, 0, -2]
[5, 9, 0]
[0, 1, 2]
```


시작과 도착이 같으면 `[start]`를 반환한다. 도달할 수 없으면 `[]`다. 이 함수에는 `floyd_warshall`이 성공적으로 반환한 같은 실행의 두 표만 전달하며, 호출자가 두 표를 임의로 수정하지 않았다고 가정한다. 음수 사이클 검사는 거리 계산 함수에서 이미 끝났으므로 복원할 때 전체 대각선을 다시 훑지 않는다.

> `[[INF] * n] * n`으로 만들면 모든 행이 같은 목록을 가리킨다. 한 칸을 바꿨는데 여러 행이 함께 바뀌므로, 반드시 위 코드처럼 리스트 컴프리헨션을 사용한다.

### 6.5 실생활 상황을 입력 데이터로 바꾸기

**상황:** 작은 물류센터의 모든 작업장 쌍에 대해 최소 이동 시간을 미리 계산하고, 작업 요청이 올 때마다 바로 조회하고 싶다.

| 현실의 정보 | 코드 표현 |
|---|---|
| 입고장·검수장·출고장 | 정점 |
| 통행 가능한 연결 통로 | 간선 |
| 통로 이동 시간 | 음수가 아닌 가중치 |
| 일방통행 통로 | 방향 간선 한 개 |
| 양방향 통로 | `directed=False`로 양쪽에 같은 비용 저장 |
| 작업장 쌍마다 필요한 최소 이동 시간 | `dist[i][j]` |
| 실제로 안내할 이동 순서 | `reconstruct_floyd_path(...)` |

다음 코드는 위 함수들 아래에 붙여 실행할 수 있다. 여기서는 일방통행을 가정한다.

```python
places = ["입고장", "검수장", "출고장"]
index = {name: i for i, name in enumerate(places)}
routes = [
    ("입고장", "검수장", 4),
    ("입고장", "출고장", 10),
    ("검수장", "출고장", 2),
    ("출고장", "입고장", 5),
]
edges = [(index[a], index[b], minutes) for a, b, minutes in routes]
dist, next_hop = floyd_warshall(len(places), edges)

start, end = index["입고장"], index["출고장"]
path = reconstruct_floyd_path(dist, next_hop, start, end)
if not path:
    print("이동할 수 없습니다.")
else:
    print("최소 이동 시간:", dist[start][end])
    print(" → ".join(places[v] for v in path))
```

실행 결과:

```text
최소 이동 시간: 6
입고장 → 검수장 → 출고장
```

한 번 계산한 뒤 최소 시간만 조회하면 `dist[start][end]` 접근은 O(1)이다. 다만 실제 경로를 목록으로 복원하는 데는 경로에 포함된 정점 수만큼 시간이 든다.

통로가 바뀌면 기존 거리표가 틀릴 수 있으므로 다시 계산해야 한다. 작업장이 매우 많거나 통로가 적은 그래프에서는, 모든 쌍 계산 대신 필요한 출발점에서 다익스트라를 실행하는 방법도 비교한다.

### 6.6 음수 사이클 처리와 복잡도

- 플로이드–워셜은 음수 간선을 허용한다. 유한한 최단 거리를 구하려면 해당 정점 쌍이 음수 사이클의 영향을 받지 않아야 한다.
- 계산 후 `dist[k][k] < 0`인 k가 있으면 음수 사이클이 존재한다.
- 어떤 i→j가 영향을 받는 정확한 조건은 “i에서 음수 사이클에 도달할 수 있고, 그 사이클에서 j로 갈 수 있다”다.
- 위 코드는 입문용으로 음수 사이클을 하나라도 발견하면 `ValueError`를 발생시킨다. 영향받지 않는 쌍의 결과까지 따로 돌려주는 기능은 구현하지 않았다.
- 시간은 3중 반복 때문에 **O(V³)**이며, 간선 초기화까지 엄밀히 포함하면 **O(V³+E)**다.
- 거리표와 경로표의 추가 공간은 **O(V²)**다. 입력 간선 목록까지 포함하면 **O(V²+E)**다.
- 경로표가 필요 없으면 `next_hop`을 생략할 수 있지만, 거리표 자체의 O(V²) 공간은 필요하다.
- 여러 직접 간선은 최솟값을 저장한다. 자기 루프도 기존 값과 비교하므로 음수 자기 루프를 놓치지 않는다.
- 구현의 유한한 가중치는 정수라고 가정하면 비교가 단순하다. 소수 비용을 쓰는 실제 서비스에서는 부동소수점 오차 처리도 따로 설계해야 한다.

발표 한 문장: **“플로이드–워셜은 중간 정점을 하나씩 허용하면서, 모든 출발·도착 쌍의 거리를 표에서 갱신합니다.”**

## 7. MST 공통 원리: 이동 비용 대신 연결 비용을 최소화한다

### 7.1 신장 트리부터 이해하기

다섯 건물 A, B, C, D, E에 통신 케이블을 설치한다고 생각하자. 어느 두 건물 사이든 연결된 케이블을 따라 통신할 수 있으면 된다. 모든 건물 쌍에 직접 케이블을 깔 필요는 없다.

- **신장(spanning)**: 원래 그래프의 모든 정점을 포함한다.
- **트리(tree)**: 연결되어 있고 사이클이 없는 무방향 그래프다.
- **신장 트리**: 모든 정점을 포함하는 트리다.
- **최소 신장 트리(MST)**: 가능한 신장 트리 중 선택한 간선 가중치의 합이 가장 작은 것이다.

정점이 `V`개인 트리는 간선이 정확히 `V - 1`개다. 따라서 건물 5개를 MST로 연결하면 케이블 구간은 4개다.

단, **아무 간선이나 4개 고르면 되는 것은 아니다.** A, B, C 사이에 삼각형을 만들고 D-E만 연결해도 간선은 4개지만, 두 덩어리로 분리되어 있다. 크루스칼은 사이클을 막으면서 간선을 선택하고, 프림은 이미 연결된 덩어리를 확장한다. 이런 조건과 함께 `V - 1`개를 선택해야 트리가 된다.

### 7.2 공통 예제

아래 비용은 설명을 위한 가상의 값이며 단위는 모두 같다고 가정한다. 간선은 **무방향**이다.

| 간선 | 설치 비용 | 간선 | 설치 비용 |
|---|---:|---|---:|
| A-B | 4 | A-C | 1 |
| B-C | 2 | B-D | 5 |
| C-D | 8 | C-E | 10 |
| D-E | 2 | | |

```text
    A ──4── B ──5── D
     ╲      │      ╱│
      1     2     8 │2
       ╲    │   ╱   │
            C ──10─ E
```

그림보다 간선 표를 기준으로 계산하자. 정점 번호는 `A=0, B=1, C=2, D=3, E=4`다.

MST의 한 결과는 `A-C(1), B-C(2), D-E(2), B-D(5)`다. 총비용은 `1 + 2 + 2 + 5 = 10`이다.

이 트리에서 A에서 D까지 이동하면 `A → C → B → D`이고 비용은 `1 + 2 + 5 = 8`이다. 이 예제에서는 최단 거리와 같지만 **MST의 모든 정점 쌍 경로가 항상 최단인 것은 아니다.** 예를 들어 A-B=2, B-C=2, A-C=3인 삼각형의 MST는 A-B와 B-C를 골라 총비용 4를 만든다. 그 MST에서 A→C의 경로 비용은 4지만, 원래 그래프의 최단 거리는 직접 간선의 3이다.

### 7.3 왜 싼 간선을 골라도 될까? 컷의 직관

모든 정점을 두 그룹으로 나누는 것을 **컷(cut)**이라고 한다. 예를 들어 `{A, C}`와 `{B, D, E}`로 나누자. 모든 정점을 연결하려면 두 그룹 사이를 건너는 간선이 적어도 하나 필요하다.

이 컷을 건너는 간선은 C-B(2), A-B(4), C-D(8), C-E(10)이다. 가장 싼 C-B(2)를 선택하는 것은 안전하다. 그 간선을 포함하지 않는 MST가 있다면, C-B를 추가해 생긴 사이클에서 같은 컷을 건너는 다른 간선을 빼면 된다. 뺀 간선은 C-B보다 싸지 않으므로 총비용이 증가하지 않는다.

이것이 **컷 속성**의 핵심이다. 최소 간선이 여러 개면 그중 하나를 포함하는 MST가 존재한다는 뜻이지, 모든 동률 간선을 반드시 포함한다는 뜻은 아니다.

- 크루스칼: 서로 다른 연결 덩어리를 잇는 가장 싼 간선을 고른다.
- 프림: 현재 연결된 정점 집합과 나머지 사이를 잇는 가장 싼 간선을 고른다.

두 알고리즘은 정답의 총비용이 같지만, 간선 비용이 같은 경우 선택한 간선 집합이나 선택 순서는 달라질 수 있다. **가중치가 모두 다르면 MST는 유일하다.** 같은 가중치가 있다고 반드시 MST가 여러 개인 것은 아니다. 예를 들어 원래 그래프가 이미 트리라면 비용이 같아도 선택은 하나뿐이다.

### 7.4 MST가 요구하는 입력 조건

| 조건 | 의미 |
|---|---|
| 무방향 그래프 | 방향이 있는 최소 연결 문제는 일반적인 MST와 다르다. |
| 연결 그래프 | 연결되지 않았다면 모든 정점을 잇는 하나의 신장 트리가 없다. |
| 음수 가중치 허용 | MST는 사이클 없이 정해진 개수의 간선을 선택하므로 음수도 처리한다. |
| 같은 비용 허용 | 정렬 순서나 힙의 동률 처리에 따라 선택 결과가 달라질 수 있다. |
| 평행 간선 허용 | 같은 두 정점 사이에 여러 간선이 있어도 싼 것을 선택할 수 있다. |
| 자기 루프 무시 | 정점을 자기 자신에 연결하는 간선은 신장 트리에 도움이 되지 않는다. |

연결되지 않은 그래프에서는 각 연결 요소의 MST를 합친 **최소 신장 포리스트**를 구할 수 있다. 아래 함수들은 요청한 결과가 하나의 MST인지 명확히 확인하기 위해, 연결되지 않은 입력에는 `ValueError`를 발생시킨다. 정점 수는 `n >= 1`, 정점 번호는 `0`부터 `n - 1`까지인 유효한 정수라고 가정한다.

## 8. 크루스칼: 간선을 싼 순서대로 검토한다

### 8.1 먼저 사람이 직접 골라보기

간선을 비용순으로 정렬하고, 사이클을 만들지 않는 간선만 선택한다. 여기서는 동률이면 정점 번호순으로 정렬한다.

| 순서 | 검토할 간선 | 선택 여부 | 이유 | 누적 비용 |
|---:|---|---|---|---:|
| 1 | A-C(1) | 선택 | A와 C가 다른 덩어리다. | 1 |
| 2 | B-C(2) | 선택 | B와 `{A,C}`가 다른 덩어리다. | 3 |
| 3 | D-E(2) | 선택 | D와 E가 다른 덩어리다. | 5 |
| 4 | A-B(4) | 제외 | A와 B는 이미 C를 통해 연결되어 있다. | 5 |
| 5 | B-D(5) | 선택 | `{A,B,C}`와 `{D,E}`를 합친다. | 10 |
| 6 | C-D(8) | 검토 전 종료 | 이미 4개를 골랐다. | 10 |
| 7 | C-E(10) | 검토 전 종료 | 이미 4개를 골랐다. | 10 |

중요한 질문은 “이번 간선을 넣으면 사이클이 생기는가?”다. 무방향 그래프에서 두 끝점이 이미 연결되어 있다면, 그 둘을 다시 연결하는 간선은 사이클을 만든다.

### 8.2 Union-Find는 무엇을 저장할까?

Union-Find(서로소 집합)는 정점들을 **서로 겹치지 않는 연결 덩어리**로 관리한다.

- `find(x)`: x가 속한 덩어리의 대표 정점을 찾는다.
- `union(a, b)`: a와 b가 속한 덩어리를 합친다.

처음에는 `{A}`, `{B}`, `{C}`, `{D}`, `{E}`다. A-C를 고르면 `{A,C}`, B-C를 고르면 `{A,B,C}`, D-E를 고르면 `{D,E}`가 된다. 이제 `find(A) == find(B)`이므로 A-B는 제외한다.

`parent[x]`는 **집합 대표를 찾기 위한 부모**다. 실제로 선택한 MST 간선의 부모 관계를 뜻하지 않는다. 합치는 과정에서 대표로 A를 쓰더라도, 선택한 실제 간선은 B-C일 수 있다.

빠르게 처리하려고 두 기법을 쓴다.

1. **경로 압축**: 대표를 찾아가는 길을 짧게 바꿔 다음 검색을 빠르게 한다. 아래 코드는 부모를 조부모로 바꾸는 반복형 방식을 쓴다.
2. **크기 기준 합치기**: 작은 집합의 대표를 큰 집합의 대표 아래에 붙인다.

### 8.3 Python 구현

입력 간선은 `(출발 정점, 도착 정점, 비용)`이다. 무방향 간선을 한 번씩 넣으면 된다. 코드 옆 주석으로 핵심 동작을 확인한다.

```python
def kruskal(n, edges):                                      # 정점 수와 간선 목록을 받는다
    if n < 1:                                               # 정점이 없는 입력인지 검사한다
        raise ValueError("정점은 하나 이상이어야 합니다.")     # 잘못된 정점 수를 알린다
    parent = list(range(n))                                  # 처음에는 모든 정점을 자기 집합의 대표로 둔다
    size = [1] * n                                          # 각 집합의 크기를 1로 둔다
    def find(x):                                            # 집합 대표를 찾는 내부 함수를 정의한다
        while parent[x] != x:                               # 현재 정점이 대표가 아니면 부모를 계속 따라간다
            parent[x] = parent[parent[x]]                   # 현재 정점의 부모를 조부모로 바꾼다
            x = parent[x]                                   # 바뀐 부모 위치로 이동한다
        return x                                            # 집합의 대표를 반환한다
    total = 0                                               # 선택한 비용의 합을 0으로 시작한다
    chosen = []                                             # 선택한 실제 간선을 저장한다
    ordered = sorted(edges, key=lambda e: (e[2], e[0], e[1])) # 비용, u, v 순으로 새 목록을 정렬한다
    for u, v, weight in ordered:                             # 정렬된 간선을 하나씩 꺼낸다
        root_u = find(u)                                    # u의 집합 대표를 찾는다
        root_v = find(v)                                    # v의 집합 대표를 찾는다
        if root_u == root_v:                                # 두 대표가 같은지 비교한다
            continue                                        # 현재 간선을 건너뛴다
        if size[root_u] < size[root_v]:                     # u 쪽 집합이 더 작은지 검사한다
            root_u, root_v = root_v, root_u                  # 대표 변수의 이름을 서로 바꾼다
        parent[root_v] = root_u                             # 작은 집합 대표의 부모를 큰 집합 대표로 바꾼다
        size[root_u] += size[root_v]                        # 큰 집합의 크기를 갱신한다
        chosen.append((u, v, weight))                       # 현재 간선을 결과에 넣는다
        total += weight                                     # 현재 비용을 총비용에 더한다
        if len(chosen) == n - 1:                            # 간선을 `n - 1`개 골랐는지 확인한다
            break                                           # 반복을 끝낸다
    if len(chosen) != n - 1:                                # 선택한 간선 수가 부족한지 확인한다
        raise ValueError("연결되지 않은 그래프입니다.")        # MST가 없음을 오류로 알린다
    return total, chosen                                    # 총비용과 선택한 간선을 반환한다
```


`n=1`이고 간선이 없다면 선택 간선 수는 `0 = n - 1`이며, 비용 0의 올바른 결과가 나온다. 자기 루프는 두 끝점의 대표가 같아서 자동으로 제외된다.

### 8.4 실행 예제

```python
mst_edges = [
    (0, 1, 4),  # A-B
    (0, 2, 1),  # A-C
    (1, 2, 2),  # B-C
    (1, 3, 5),  # B-D
    (2, 3, 8),  # C-D
    (2, 4, 10), # C-E
    (3, 4, 2),  # D-E
]
total, selected = kruskal(5, mst_edges)
print(total)
print(selected)
# 집합의 대표를 반환한다
# [(0, 2, 1), (1, 2, 2), (3, 4, 2), (1, 3, 5)]
```

### 8.5 복잡도와 실수 포인트

정점 수를 `V`, 원래 무방향 간선 수를 `E`라고 하자. 정렬은 `O(E log(E + 1))`, 집합 연산 전체는 경로 압축과 크기 기준 합치기를 적용하면 `O(E α(V))`다. `α(V)`는 역 아커만 함수로, 현실적인 입력 크기에서는 매우 작다. 초기화까지 포함한 통상적인 상한은 **`O(V + E log(E + 1))`**이며, `sorted`가 만드는 복사본과 결과 목록을 포함한 공간은 **`O(V + E)`**다. 보통 `O(E log E)`라고 요약한다.

- `(u, v, w)`를 그대로 정렬하면 u부터 정렬된다. 반드시 비용 `e[2]`를 첫 기준으로 쓴다.
- `parent[u] == parent[v]`만 비교하면 안 된다. 바로 위 부모가 달라도 최종 대표는 같을 수 있다. 반드시 `find(u) == find(v)`로 비교한다.
- 대표끼리 합쳐야 한다. `parent[v] = u`처럼 원래 정점에 바로 연결하면 집합 구조를 잘못 바꿀 수 있다.
- 정렬만 하고 싼 간선 `V - 1`개를 고르면 사이클이나 단절이 생길 수 있다.
- 간선 비용이 음수여도 이 구현은 사용할 수 있다. 다익스트라의 음수 제한과 혼동하지 않는다.

## 9. 프림: 현재 연결망에 가장 싸게 한 정점씩 추가한다

### 9.1 크루스칼과 시작 관점이 다르다

크루스칼은 그래프 전체의 간선을 정렬한다. 프림은 출발 정점 하나에서 시작해 **이미 연결된 정점 집합과 아직 포함되지 않은 정점 사이**의 가장 싼 간선을 고른다.

A에서 시작하면 현재 연결망은 `{A}`다. 후보는 A-C(1), A-B(4)다. A-C를 고르면 연결망이 `{A,C}`가 된다. 이제 C-B(2), C-D(8), C-E(10)도 후보에 추가한다. 이때 A-B(4)는 아직 후보에 남아 있지만 C-B(2)가 더 싸므로 B는 C를 통해 연결된다.

### 9.2 단계별 실행

표의 후보는 **현재 연결망에서 바깥 정점으로 나가는 유효한 간선**만 적었다. 실제 힙에는 나중에 쓸모없어진 항목도 남아 있을 수 있다.

| 단계 | 추가 전 연결망 | 유효한 후보 | 선택 | 추가 후 총비용 |
|---:|---|---|---|---:|
| 시작 | 없음 | 시작 정점 A | A를 비용 0으로 시작 | 0 |
| 1 | `{A}` | A-C(1), A-B(4) | A-C(1) | 1 |
| 2 | `{A,C}` | C-B(2), A-B(4), C-D(8), C-E(10) | C-B(2) | 3 |
| 3 | `{A,B,C}` | B-D(5), C-D(8), C-E(10) | B-D(5) | 8 |
| 4 | `{A,B,C,D}` | D-E(2), C-E(10) | D-E(2) | 10 |

여기서 선택 비용은 `1 → 2 → 5 → 2`다. **프림이 선택하는 간선 비용은 계속 커질 필요가 없다.** D가 연결되면서 더 싼 D-E(2)를 새로 발견했기 때문이다.

실제 힙에서는 B를 C-B(2)로 연결한 뒤에도 A-B(4) 항목이 남는다. 이 항목을 꺼냈을 때 B는 이미 방문한 정점이므로 버린다. 이것이 아래 구현의 `visited` 검사다.

### 9.3 Python 구현

인접 리스트 `graph[u]`에는 `(이웃 정점, 간선 비용)`을 넣는다. 무방향 간선은 양쪽에 넣는다. 함수는 정점 수 `n`, 인접 리스트 `graph`, 시작점 `start`를 받는다.

```python
import heapq                                                   # 최소 힙 기능을 불러온다
def prim(n, graph, start=0):                                    # MST를 구하는 함수를 정의한다
    if n < 1 or not (0 <= start < n):                           # 정점 수와 시작점 범위를 검사한다
        raise ValueError("정점 수 또는 시작점을 확인하세요.")    # 입력 조건 위반을 알린다
    visited = [False] * n                                      # 아직 어떤 정점도 포함하지 않았다고 표시한다
    heap = [(0, start, -1)]                                    # 시작 정점에 비용 0짜리 가상 진입 항목을 넣는다
    total = 0                                                  # 총비용을 0으로 시작한다
    chosen = []                                                # 선택한 실제 간선을 담을 목록을 만든다
    count = 0                                                  # 포함한 정점 수를 0으로 시작한다
    while heap:                                                # 후보가 있는 동안 반복한다
        weight, node, previous = heapq.heappop(heap)           # 비용이 가장 작은 후보를 꺼낸다
        if visited[node]:                                     # 이 정점을 이미 연결했는지 확인한다
            continue                                           # 이미 연결한 정점의 후보를 버린다
        visited[node] = True                                  # 현재 정점을 MST 정점 집합에 포함한다
        count += 1                                             # 포함 정점 수를 늘린다
        total += weight                                        # 선택 비용을 더한다
        if previous != -1:                                    # 가상의 시작 항목인지 구분한다
            chosen.append((previous, node, weight))           # 실제 선택 간선을 저장한다
        if count == n:                                        # 모든 정점을 포함했는지 확인한다
            break                                              # 반복을 끝낸다
        for neighbor, next_weight in graph[node]:             # 새로 연결한 정점의 인접 간선을 본다
            if not visited[neighbor]:                         # 이웃이 아직 연결망 밖에 있는지 확인한다
                heapq.heappush(                                # 간선 비용과 양 끝점을 힙에 넣는다
                    heap, (next_weight, neighbor, node)
                )

    if count != n:                                             # 후보가 끝났는데 일부 정점이 빠졌는지 확인한다
        raise ValueError("연결되지 않은 그래프입니다.")           # 하나의 MST가 없음을 알린다
    return total, chosen                                       # 총비용과 선택한 간선을 반환한다
```

`-1`은 “시작 정점에는 이전 정점이 없다”는 표시다. 간선 비용이 -1인 것과는 관계없다. 정점 번호가 `0` 이상이므로 이전 정점 표시로 구분해서 쓸 수 있다.


### 9.4 실행 예제

```python
# 앞 절 mst_edges와 같은 데이터를 사용한다.
# 이 블록만 실행하려면 8.4의 mst_edges 정의와 9.3의 함수를 함께 복사한다.
mst_graph = [[] for _ in range(5)]
for u, v, weight in mst_edges:
    mst_graph[u].append((v, weight))
    mst_graph[v].append((u, weight))

total, selected = prim(5, mst_graph, start=0)
print(total)
print(selected)
# 후보가 있는 동안 반복한다
# [(0, 2, 1), (2, 1, 2), (1, 3, 5), (3, 4, 2)]
```

첫 두 줄의 인접 리스트 구성은 “건물 u에서 v로 연결할 수 있다”와 그 반대 방향을 각각 기록한다. 무방향 간선을 자료구조에서 두 번 저장해도, 실제 선택 간선의 비용을 두 번 더하는 것은 아니다. 이미 포함된 정점은 `visited`로 제외한다.

크루스칼 결과의 `(1, 2, 2)`와 프림 결과의 `(2, 1, 2)`는 같은 무방향 간선 B-C다. 결과 목록 순서와 끝점 순서가 달라도 총비용과 실제 간선 집합이 같을 수 있다.

### 9.5 복잡도와 실수 포인트

이 구현은 같은 목적지의 후보를 여러 개 힙에 넣고, 나중에 오래된 후보를 버리는 방식이다. 힙의 크기는 `V`가 아니라 **최대 `O(E)`**가 될 수 있다. 인접 리스트까지 포함한 시간 상한은 **`O(V + E log(E + 1))`**, 공간은 **`O(V + E)`**다. 단순 연결 그래프에서는 `E <= V(V - 1)/2`이므로 보통 **`O(E log V)`**라고 적는다.

정점마다 최선 후보를 하나씩 관리하는 다른 힙 구현은 분석이 달라질 수 있다. 또한 인접 행렬을 사용해 매번 가장 싼 정점을 선형 탐색하는 프림은 **`O(V²)` 시간, `O(V²)` 공간**이며, 간선이 매우 많은 그래프에서 고려할 수 있다.

- `total += weight`를 방문 검사보다 먼저 하면 오래된 후보의 비용까지 더한다.
- 힙에 넣을 때 `visited=True`로 표시하면, 나중에 발견한 더 싼 연결 후보를 선택하지 못할 수 있다. **힙에서 꺼내 채택할 때 방문 처리한다.**
- 인접 리스트에 한쪽 방향만 넣으면 무방향 연결망을 올바르게 탐색하지 못한다.
- 시작 정점은 비용 0으로 처리하지만, 나머지 정점은 실제 간선 비용을 더한다.
- 연결되지 않은 그래프에서 한 시작점만으로 전체 MST를 만들 수 없다. 반환 전에 방문 정점 수를 확인한다.

### 9.6 다익스트라와 프림: 코드가 비슷한데 무엇이 다를까?

두 알고리즘 모두 인접 리스트와 최소 힙을 쓰지만 **힙에 넣는 비용의 의미**가 다르다.

| 비교 | 다익스트라 | 프림 |
|---|---|---|
| 목표 | 시작점에서 각 정점까지의 이동 비용 최소화 | 모든 정점을 연결하는 간선 비용 합 최소화 |
| 힙의 비용 | 시작점에서 해당 정점까지의 누적 거리 | 현재 연결망에서 새 정점으로 들어가는 간선 하나의 비용 |
| 새 후보 계산 | `현재까지 거리 + 새 간선 비용` | `새 간선 비용` |
| 핵심 배열 | `dist`, 필요하면 `parent` | `visited`, 필요하면 정점별 최선 연결 비용 |
| 음수 간선 | 일반적으로 사용할 수 없다. | 무방향 MST에서는 사용할 수 있다. |
| 결과 구조 | 최단 경로 트리를 만들 수 있다. | 최소 신장 트리를 만든다. |

예를 들어 A→C까지 1이고 C-B가 2일 때, 다익스트라에서 B의 후보 거리는 `1 + 2 = 3`이다. 프림에서 C-B를 선택할 비용은 간선 자체의 `2`다. 프림에서도 최종 총비용에 각 선택 간선 비용을 더하지만, **다음 후보를 비교하는 힙 키에 출발점 누적 거리를 넣지 않는다.**

### 9.7 실제 활용을 입력 데이터와 연결하기: 케이블 설치 계획

현실의 문장을 다음처럼 데이터로 바꾼다.

| 현실의 정보 | 그래프의 정보 | 코드에서 쓰는 값 |
|---|---|---|
| 연결할 건물 | 정점 | `names`, `id_of` |
| 시공 가능한 두 건물의 구간 | 무방향 간선 | `(u, v, weight)` |
| 해당 구간의 고정 설치 견적 | 간선 가중치 | `weight` |
| 선택한 설치 구간 | MST 간선 | `selected` |
| 전체 설치 비용 | 선택 가중치의 합 | `total` |

```python
names = ["본관", "도서관", "실습관", "기숙사", "체육관"]
id_of = {name: index for index, name in enumerate(names)}

# 실제 견적이 아닌 학습용 가상 비용이다.
quotes = [
    ("본관", "도서관", 4),
    ("본관", "실습관", 1),
    ("도서관", "실습관", 2),
    ("도서관", "기숙사", 5),
    ("실습관", "기숙사", 8),
    ("실습관", "체육관", 10),
    ("기숙사", "체육관", 2),
]
cable_edges = [
    (id_of[left], id_of[right], cost)
    for left, right, cost in quotes
]
total, selected = kruskal(len(names), cable_edges)
print("총비용:", total)
for u, v, cost in selected:
    print(names[u], "-", names[v], "비용:", cost)
# 총비용: 10
# 본관 - 실습관 비용: 1
# 도서관 - 실습관 비용: 2
# 기숙사 - 체육관 비용: 2
# 도서관 - 기숙사 비용: 5
```

`enumerate`는 이름에 0부터 번호를 붙인다. `id_of`는 건물명을 배열 인덱스로 바꾸고, 리스트 컴프리헨션은 견적 데이터를 함수가 받는 `(u, v, 비용)` 형식으로 변환한다. 결과를 보여줄 때는 `names[u]`로 다시 건물명을 찾는다. **알고리즘에 현실의 건물명을 직접 이해시키는 대신, 현실 데이터를 정점·간선·가중치로 번역하는 것이다.**

이 모델은 모든 건물을 연결하는 고정 설치비의 합을 최소화한다. 일부 건물 사이의 최단 통신 지연, 대역폭 제한, 장애 시 우회선, 필수 연결 구간 같은 조건은 이 코드에 들어 있지 않다. 그런 조건이 실제 요구사항이면 데이터와 문제 정의를 더 확장해야 한다. 예를 들어 MST는 간선 하나만 끊어져도 연결이 분리되므로, 우회선 확보가 필요한 설계의 최종 답으로 그대로 사용할 수는 없다.

## 10. 실제 문제를 그래프와 코드로 바꾸는 방법

### 10.1 알고리즘을 고르기 전에 적어 볼 다섯 문장

1. **정점은 무엇인가?** 건물, 정류장, 작업 단계, 또는 상태인가?
2. **간선은 언제 존재하는가?** 직접 이동/시공이 가능한 경우인가?
3. **방향이 있는가?** 일방통행이면 반대 간선을 자동으로 만들면 안 된다.
4. **가중치는 무엇이며 합산 가능한가?** 분, 원, 설치비 등 단위를 통일한다.
5. **요구 결과는 무엇인가?** 한 출발점의 거리, 모든 쌍의 거리, 실제 경로, 연결 계획 중 무엇인가?

| 문제 문장 | 정점 | 간선 | 가중치 | 함수와 결과 사용 |
|---|---|---|---|---|
| 기숙사에서 모든 시설까지 최소 도보 시간 | 시설 | 걸을 수 있는 통로 | 분, 0 이상 | `dijkstra` → `dist[v]`, `restore_path` |
| 반복 가능한 구간 보상을 포함한 최소 순비용 | 장소/상태 | 허용된 이동 | 요금−보상, 음수 가능 | `bellman_ford` → 거리 또는 음수 사이클 오류 |
| 작은 물류센터의 모든 작업장 쌍 이동 시간 조회 | 작업장 | 이동 통로 | 분 | `floyd_warshall` → `dist[i][j]` |
| 모든 건물의 최소 설치비 케이블 계획 | 건물 | 시공 가능한 구간 | 구간별 설치 견적 | `kruskal` 또는 `prim` → `total`, `chosen` |

‘실제로 어떻게 쓰이는가’의 핵심은 이 표의 변환이다. 알고리즘에 ‘도서관’이라는 단어를 넣는 것이 아니라, 장소를 번호로 바꾸고 이동/연결 규칙을 간선으로 넣는다. 앞 장의 실행 예제들이 각각 이 변환을 보여 준다.

### 10.2 같은 도시 데이터라도 가중치와 질문이 다르면 답이 달라진다

도로의 **주행 시간**을 가중치로 두고 ‘A→B 도착’을 묻는다면 최단 경로다. 도로 옆 통신선의 **설치비**를 가중치로 두고 ‘모든 시설 연결’을 묻는다면 MST다.

같은 두 정점 사이의 값이라도 `5분`과 `500만원`은 다른 가중치다. 한 간선 목록에 단위가 다른 값을 섞으면 최솟값 자체가 의미 없어질 수 있다.

또한 ‘도서관을 반드시 들러야 한다’면 도달 가능한 구간의 최단 거리 `d(출발,도서관)+d(도서관,도착)`를 이용할 수 있다. 그 밖에 시간대·이용 횟수·방문 제한처럼 미래 선택에 영향을 주는 조건은 상태에 넣어야 한다.

### 10.3 한 번만 쓸 수 있는 할인은 ‘상태’를 늘려 표현한다

**상황:** 방향 도로 요금이 있고, 전체 이동 중 딱 한 번까지 한 도로의 요금을 절반으로 할인할 수 있다. 홀수 요금의 절반은 내림한다. 모든 원래 요금은 0 이상이다.

장소만 정점으로 쓰면 그 장소에 도착했을 때 할인권이 남아 있는지 구분할 수 없다. 따라서 정점을 `(장소, 사용 여부)`로 만든다.

```text
(장소 u, 미사용) → (장소 v, 미사용): 원래 요금
(장소 u, 사용함) → (장소 v, 사용함): 원래 요금
(장소 u, 미사용) → (장소 v, 사용함): 할인 요금

‘사용함 → 미사용’ 간선은 만들지 않는다.
```

장소 번호가 `u`이고 상태가 0/1이면 `2*u+상태`로 번호를 만든다. 정점 수는 원래의 2배다. 새 가중치도 모두 0 이상이므로 다익스트라를 쓸 수 있다.

```python
city_count = 3                                    # 장소 0, 1, 2
fare_edges = [(0, 1, 6), (1, 2, 6), (0, 2, 20)] # 방향 도로와 원래 요금
state_graph = [[] for _ in range(2 * city_count)] # 장소별 미사용/사용 상태
for u, v, fare in fare_edges:
    state_graph[2*u].append((2*v, fare))          # 미사용을 유지하며 정상 결제
    state_graph[2*u+1].append((2*v+1, fare))      # 이미 썼다면 정상 결제
    state_graph[2*u].append((2*v+1, fare // 2))   # 이번 도로에서 할인권 사용

state_start = 2 * 0                              # (장소 0, 미사용)
state_dist, state_parent = dijkstra(2*city_count, state_graph, state_start)
state_targets = [2*2, 2*2+1]                    # 목적지 2의 미사용/사용 상태
best_state = min(state_targets, key=lambda s: state_dist[s])
state_path = restore_path(state_parent, state_start, best_state)
print(state_dist[best_state])
print([(s // 2, s % 2) for s in state_path])      # 상태 번호를 (장소, 사용 여부)로 복원
```

```text
9
[(0, 0), (1, 1), (2, 1)]
```

이 실행은 첫 도로에서 할인해 `3+6=9`를 얻는다. 두 번째 도로에서 할인한 `6+3=9`도 최적이다. 엄격한 `<` 갱신이므로 같은 비용의 나중 경로로 부모를 바꾸지 않는다. 직접 도로를 할인한 10보다 두 구간 경로 9가 싸다.

**무엇을 어디에 추가했나?** 할인 규칙은 다익스트라 함수 내부를 바꾸지 않고 `state_graph`를 만드는 부분에 넣었다. ‘사용 여부’라는 기억을 정점에 포함한 것이다. 이 방식은 열쇠 소유, 남은 이동 횟수 등에도 이어지지만 상태 수와 간선 수가 함께 늘어난다는 점을 계산해야 한다.

### 10.4 MST로 설치 계획을 만들 때의 경계

9.7의 케이블 코드는 구간별 견적이 고정이고 총비용이 간선 비용의 합이라고 가정한다. 설치 불가 구간은 큰 수로 넣는 대신 간선을 만들지 않으면 된다. 그 결과 연결되지 않으면 코드가 오류를 내므로, 견적과 시공 가능 구간을 다시 검토한다.

‘특정 구간 필수’라면 크루스칼에서 필수 간선들을 먼저 합치되, 그 자체가 사이클을 만드는지 검사하는 식으로 확장할 수 있다. ‘어떤 한 선이 끊어져도 통신 가능’이라는 조건은 트리만으로 충족할 수 없으므로 일반 MST와 다른 문제다.

## 11. 복잡도·실수·자주 묻는 질문

### 11.1 왜 그런 시간 복잡도가 나오는가?

| 알고리즘 | 반복의 단위 | 가장 큰 비용의 출처 |
|---|---|---|
| 다익스트라 | 유효한 정점 확장, 간선별 개선 후보 | 간선 검사와 힙 삽입·삭제 |
| 벨만–포드 | 최대 V−1회 × 모든 E개 간선 | 반복 완화 `VE` |
| 플로이드–워셜 | 모든 k × 모든 i × 모든 j | 세 개의 정점 반복 `V³` |
| 크루스칼 | 전체 간선 정렬 후 집합 합치기 | 정렬 `E log E` |
| 프림 | 정점 확장마다 바깥 간선 후보 추가 | 간선 후보의 힙 삽입·삭제 |

예를 들어 `V=100, E=500`이면 벨만–포드의 주요 완화 확인은 최대 약 `99×500=49,500`회다. 플로이드–워셜의 세 반복 조합은 `100³=1,000,000`개다. 실제 실행 시간은 Python 연산·그래프 형태·조기 종료에 따라 달라진다.

`V=1,000`이면 `V³=1,000,000,000`이다. 따라서 플로이드–워셜은 정점이 조금만 늘어도 부담이 크다. `V=500이면 항상 가능` 같은 고정 기준 대신 시간 제한과 구현 환경을 확인한다. 행렬의 칸 수 `V²`와 Python 객체의 메모리 부담도 함께 본다.

가중치가 음수가 아닌 희소 그래프에서 모든 쌍이 필요하면 다익스트라를 V번 실행하는 방법도 비교한다. 이 자료 구현 기준 시간은 `O(V(V+E log(E+1)))`이고, 결과를 전부 보관하면 거리 저장만으로도 `O(V²)`가 든다. 행 하나씩 출력하면 결과 저장량을 줄일 수 있다.

### 11.2 공통 실수 체크표

| 실수 | 왜 틀리나? | 확인 방법 |
|---|---|---|
| 최단 경로와 MST를 같은 목표로 생각 | 경로 합과 전체 간선 합이 다름 | 1.3 삼각형을 다시 계산 |
| 정점 1~V 입력을 그대로 0~V−1 배열에 사용 | 범위를 넘거나 배열이 어긋남 | 입력 시 `u-=1`, `v-=1` 등으로 한 번만 변환 |
| 무방향 간선을 한쪽에만 저장 | 반대쪽 이동/확장을 놓침 | `make_adj(..., directed=False)` |
| 방향 간선도 자동으로 양쪽 저장 | 존재하지 않는 길을 만듦 | 일방통행 여부를 먼저 읽기 |
| 간선 튜플 순서 혼동 | 비용 대신 정점을 정렬/비교 | 입력 `(u,v,w)`, 인접 `(v,w)`, 힙 형식 별도 확인 |
| `<=`이면 갱신 | 같은 비용 후보를 계속 넣거나 부모를 불필요하게 바꿈 | 본문은 모두 더 작은 `<`일 때만 갱신 |
| 간선 없음과 비용 0을 혼동 | 0원/0분 간선을 없애 버림 | 없음은 `inf` 또는 저장 안 함 |
| `[[0]*n]*n` 사용 | 내부 행 객체 공유 | 리스트 컴프리헨션 사용 |
| `INF=10**9`를 무조건 사용 | 가능한 거리보다 작으면 도달 불가 판정이 틀림 | 이 자료는 `math.inf`/`float('inf')` 사용 |
| 도달 불가인 u에서 음수 간선을 완화 | 유한한 큰 INF를 쓸 때 가짜 경로가 생김 | BF의 도달 여부 검사 유지 |
| 프림에 누적 거리를 넣음 | 최소 설치비 대신 다른 기준으로 선택 | 키는 새 간선의 비용 하나 |
| MST가 없어도 일부 총비용을 반환 | 연결되지 않은 결과를 전체 답으로 오해 | 정점 수/선택 간선 수 검사 |

### 11.3 발표에서 나올 만한 질문

**Q. 가중치가 전부 1이면 다익스트라를 써야 하나요?**

A. 쓸 수 있지만 BFS로 `O(V+E)`에 구할 수 있다. 모든 간선 비용이 같은 양수라면 간선 수가 적은 경로가 비용도 작다.

**Q. 음수 간선이 있다고 항상 음수 사이클인가요?**

A. 아니다. 방향 그래프 `A→B(-2)` 한 개에는 사이클이 없다. 다만 무방향 음수 간선을 양방향으로 해석하고 반복 이동할 수 있다면 왕복으로 비용을 계속 줄일 수 있다.

**Q. 음수 간선을 없애려고 모든 간선에 10씩 더하면 안 되나요?**

A. 경로마다 간선 수가 달라서 순위가 바뀐다. 직접 경로 비용 3과 두 간선 경로 `1+1=2`를 비교하자. 각 간선에 10을 더하면 직접은 13, 두 간선은 22가 되어 원래 더 싼 경로가 더 비싸진다. 이를 최단 경로를 보존하는 변환으로 사용할 수 없다.

**Q. 음수 사이클이 있어도 그곳을 한 번만 지나면 되지 않나요?**

A. 그러면 ‘정점/간선을 반복하지 못한다’는 별도 제약의 문제가 된다. 이 자료의 최단 경로는 반복 이동을 배제하지 않는 표준 모델이다. 음수 사이클 영향을 받는 쌍은 아무리 작은 비용을 제시해도 한 바퀴 더 돌아 더 줄일 수 있어 유한한 최솟값이 없다.

**Q. 벨만–포드는 출발점과 무관한 음수 사이클도 찾아내나요?**

A. 본문 코드는 출발점에서 도달 가능한 것만 찾는다. 그래프 전체 탐지는 모든 정점으로 비용 0 간선을 보내는 가상 출발점을 추가하는 방법으로 확장할 수 있다. 모든 거리를 0으로 시작하는 동등한 방법도 있다.

**Q. 플로이드–워셜의 i와 j 반복문은 바꿔도 되나요?**

A. `k`를 가장 바깥에 두면 안쪽 `i`, `j` 순서는 바꿔도 된다. `k`까지 임의로 섞으면 경유지 집합별 갱신이라는 의미가 깨진다.

**Q. 프림 시작점이 달라지면 비용도 달라지나요?**

A. 연결된 같은 무방향 그래프에서 최소 총비용은 같다. 동률이 있으면 선택 간선과 순서는 달라질 수 있다.

**Q. 크루스칼은 방문 배열 대신 왜 Union-Find를 쓰나요?**

A. 필요한 질문이 ‘끝점이 방문됐나?’가 아니라 ‘끝점 둘이 이미 같은 연결 요소인가?’이기 때문이다. 두 정점을 모두 전에 봤어도 서로 다른 덩어리라면 연결해야 한다.

**Q. MST에 음수 간선이 있어도 왜 괜찮나요?**

A. MST는 사이클 없는 간선 집합을 한 번 선택한다. 같은 간선을 반복해서 비용을 무한히 줄이는 문제가 아니다. 가중치 부호와 관계없이 컷 속성으로 선택을 정당화할 수 있다.

**Q. 최단 경로 트리와 MST는 둘 다 V−1개 아닌가요?**

A. 모든 정점이 도달 가능하고 올바른 부모를 하나씩 고르면 최단 경로 트리도 V−1개다. 하지만 간선 개수가 같다고 최적화 목표가 같은 것은 아니다. 1.3에서 비용이 5와 4로 달라진다. 도달 불가 정점이 있으면 출발점의 최단 경로 트리가 모든 정점을 포함하지 않는다.

**Q. 크루스칼과 프림 중 무엇을 외우는 게 좋나요?**

A. 간선 목록과 Union-Find가 익숙하면 크루스칼, 인접 리스트와 힙이 익숙하면 프림부터 재구현하자. 희소 그래프에서는 둘 다 좋은 선택이 될 수 있다. 밀집 그래프는 행렬 프림 `O(V²)`도 비교하며 ‘항상 어느 쪽이 빠르다’고 단정하지 않는다.

### 12.1 35분 발표 + 5분 질문 구성

20분으로 줄여야 하면: 개념·비교 3분, 다익스트라 3분, 벨만–포드 4분, 플로이드–워셜 4분, MST 두 개 4분, 활용·정리 2분으로 구성한다. 상태 확장과 코드 주석은 배포 자료에서 읽게 한다.

### 12.2 발표에서 바로 쓸 수 있는 연결 멘트

**시작:** “오늘은 그래프에서 비용을 줄이는 다섯 알고리즘을 보겠습니다. 먼저 무엇의 비용을 줄이는지 나누겠습니다. 목적지로 가는 이동 비용과, 모든 곳을 연결하는 설치비는 다른 문제입니다.”

**다익스트라:** “지금까지 알려진 누적 거리 중 가장 작은 후보를 꺼냅니다. 이후 간선도 모두 0 이상이므로, 더 먼 후보를 돌아와 이 거리를 줄일 수 없습니다.”

**벨만–포드로 전환:** “음수 비용이 있으면 방금의 확정 논리가 깨집니다. 그래서 확정을 서두르지 않고 모든 간선을 반복해서 확인합니다. 정점 반복이 없는 최단 경로는 최대 V−1개 간선이므로 그만큼 반복합니다.”

**플로이드–워셜로 전환:** “출발점을 매번 바꾸는 대신 모든 출발·도착 조합을 표로 만들 수도 있습니다. 중간 정점 k를 새로 허용했을 때 더 싼 경로가 생기는지 확인합니다.”

**MST로 전환:** “여기서 질문을 바꾸겠습니다. 이동할 경로가 아니라 설치할 연결망을 고른다면, 선택한 전체 간선의 합을 최소화해야 합니다.”

**크루스칼과 프림:** “크루스칼은 전체 간선 중 싼 것부터 보고, 이미 연결된 두 정점을 다시 잇지 않습니다. 프림은 한 덩어리에서 시작해서 바깥을 가장 싸게 연결합니다.”

**마무리:** “최단 경로는 경로의 합, MST는 전체 연결의 합을 줄입니다. 같은 힙을 쓰더라도 다익스트라는 누적 거리, 프림은 간선 하나의 비용을 비교합니다. 문제의 방향·음수·출발점 수를 읽고 알고리즘을 선택하겠습니다.”

### 12.3 발표 화면에 표시할 핵심 코드 다섯 줄

```text
다익스트라:       candidate = cur_dist + w
벨만–포드:       for _ in range(n - 1):  # 안에서 모든 간선 완화
플로이드–워셜:   dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
크루스칼:        if find(u) != find(v):  # 두 집합을 합치고 간선 선택
프림:            heappush(heap, (next_weight, neighbor, node))
```

이 블록은 설명용 핵심 표현이다. 본문 구현처럼 초기화·도달 여부·오래된 후보·연결 검사와 함께 써야 한다.

## 13. 재구현 체크리스트와 참고 자료

### 13.1 구현을 마쳤다면 이 입력들을 확인하기

| 확인 입력 | 기대하는 동작 |
|---|---|
| 정점 1개, 간선 없음 | 단일 출발 거리 `[0]`, FW `[[0]]`, MST 총비용 0·간선 `[]` |
| 간선 없는 정점 여러 개 | 최단 경로 도달 불가는 `inf`/경로 `[]`, MST 오류 |
| 간선 비용 0 | 실제 연결로 처리 |
| 같은 두 정점 사이 평행 간선 | 더 싼 경로/연결 선택 |
| 음수가 아닌 자기 루프 | 최단 거리 0보다 좋지 않으면 무시, MST에는 선택 안 함 |
| 음수 자기 루프 | 다익스트라 입력 거부, 도달 가능 BF 및 FW 음수 사이클 탐지 |
| 음수 간선은 있지만 음수 사이클 없음 | BF/FW는 거리 계산 가능 |
| 출발점에서 도달 불가인 음수 사이클 | BF는 해당 출발점 결과 반환, FW는 그래프 전체 음수 사이클 오류 |
| 비용이 같은 경로 또는 여러 MST | 최소 거리/총비용을 비교하고 결과 목록 동률 허용 |
| 분리된 무방향 그래프 | 크루스칼/프림 모두 전체 MST 없음 알림 |

본문 구현은 수업과 발표를 위한 명확한 입력 계약을 사용한다. 모든 함수가 정점 번호나 배열 크기까지 검증하는 범용 라이브러리는 아니다. 실제 입력 처리는 문제에서 주는 형식에 맞추고, 함수에 넣기 전 방향·번호·가중치 단위를 정리한다.

### 13.2 빈 종이에 다시 적을 핵심

- 다익스트라: 거리 배열 → 시작점 0 → 최소 누적 거리 힙 → 옛 후보 제외 → 인접 간선 완화.
- 벨만–포드: 거리 배열 → 시작점 0 → 모든 간선 V−1회 완화 → 한 번 더 개선되면 도달 가능한 음수 사이클.
- 플로이드–워셜: 거리 행렬 → 대각선 0·직접 간선 최소값 → k를 바깥에 두고 경유 비교 → 대각선 음수 검사.
- 크루스칼: 비용 정렬 → Union-Find로 대표 비교 → 다른 집합이면 합치고 선택 → V−1개 및 연결 확인.
- 프림: 시작점 비용 0 → 최소 간선 힙 → 방문 중복 제외 → 새 정점에서 바깥 간선 추가 → 전체 방문 확인.

### 13.3 개념 확인과 더 읽을 자료

아래 자료는 원리와 API를 확인하는 참고 링크다. 이 문서의 예제 그래프·코드·풀이·발표 구성은 학습 목적에 맞게 별도로 작성했다.

- [Princeton Algorithms, 4th Edition: Shortest Paths](https://algs4.cs.princeton.edu/44sp/): 완화, 음수 가중치, 다익스트라와 벨만–포드의 전제를 더 살펴볼 수 있다. 교재의 큐 기반 BF와 본문의 전체 간선 반복 구현은 형태가 다르다.
- [Carnegie Mellon 15-210: Bellman–Ford and Floyd–Warshall](https://www.cs.cmu.edu/~15210/notes/bellmanford.pdf): 벨만–포드의 간선 수 기반 사고와 플로이드–워셜의 동적 계획법을 공부할 때 참고한다.
- [Dartmouth CS31: Prim and Kruskal](https://www.cs.dartmouth.edu/~deepc/LecNotes/cs31/lec26supp.pdf): MST와 두 탐욕 알고리즘을 더 공부할 때 읽는다. 자료구조가 다른 구현의 복잡도 표기는 본문과 다를 수 있다.
- [Boost.Graph 공식 문서: Shortest Paths](https://www.boost.org/latest/libs/graph/doc/html/graph/algorithms/shortest_paths/shortest_paths_overview.html): 단일 출발점/모든 쌍 등 문제별 알고리즘 분류를 확인한다.
- [Python 공식 문서: heapq](https://docs.python.org/3/library/heapq.html): 최소 힙 삽입·삭제, 튜플 우선순위 비교를 확인한다. 본문은 오래전부터 제공되는 최소 힙 API만 사용한다.

학습이 끝났다면 한 문장으로 구분해 보자. **“출발점에서의 이동 비용을 구하는가, 모든 지점의 연결 비용을 구하는가?”** 이 질문에 답한 뒤 음수와 방향, 출발점 수를 확인하면 다섯 알고리즘을 고르는 기준이 정리된다.
