### 🗂️ 자료구조: Graph 기본 & DFS / BFS (권혜강, 윤형섭, 최승우, 최나현 발표)

*   **왜 알아야 하나**: 지도 길찾기, 친구 추천(거리 2인 사람), 웹 크롤러, 패키지·마이그레이션 의존성 순서가 모두 그래프 탐색입니다. 핵심은 **문제를 그래프로 바꾸는 눈**이고, 정점과 간선만 정하면 나머지는 DFS / BFS 템플릿이 풉니다.
*   **그래프와 트리**: 그래프 G = (V, E)는 임의의 관계를 표현하는 가장 보편적인 모델입니다. 트리는 사이클이 없고 간선이 V-1개인 특수한 그래프입니다. (2회차와 연결)
*   **표현법**

| 구분 | 인접 행렬 | 인접 리스트 |
| :---: | :---: | :---: |
| 공간 | O(V²) | O(V + E) |
| u–v 연결 확인 | O(1) | O(deg(u)) |
| u의 이웃 전부 | O(V) | O(deg(u)) |
| DFS / BFS 전체 | O(V²) | O(V + E) |
| 이럴 때 | 정점이 적고 간선이 빽빽할 때 | 간선이 듬성듬성한 대부분의 실제 그래프 |

*   정점 10만 개면 행렬은 100억 칸(약 40GB)이라 실전은 대부분 인접 리스트입니다.
*   **CS 심화(윤형섭)**: 인접 리스트는 메모리가 흩어져 캐시 미스(포인터 체이싱)가 잦습니다. 대규모 그래프 라이브러리는 연속 배열 2개(`row_ptr`, `col_idx`)에 담는 **CSR** 포맷으로 캐시 효율을 높입니다.
*   **DFS**: 스택(재귀)으로 한 갈래를 끝까지 가고, 막히면 되돌아옵니다. 순환 참조 검사(Django `CircularDependencyError`), 폴더 탐색, 백트래킹(조합·순열, N-Queen)에 씁니다.
*   **BFS**: 큐로 가까운 정점부터 한 층씩 넓혀 갑니다. 간선 비용이 모두 같으면 **처음 도착한 순간의 거리 = 최단 거리**입니다. 미로 최소 이동, 지하철 최소 정거장, N촌 찾기에 씁니다.
*   **차이는 자료구조 하나**: 스택이면 가장 최근에 찾은 정점(깊은 곳)부터, 큐면 가장 먼저 찾은 정점(가까운 곳)부터 꺼냅니다. 시간은 둘 다 O(V + E)이고, 추가 메모리는 DFS가 최대 깊이, BFS가 최대 너비에 비례합니다.
*   **문제 보고 고르기**: "최소·최단"이면 BFS, "모든 경우"면 DFS, 덩어리 개수·도달 가능 여부는 둘 다 가능합니다.
*   **구현 함정**
    *   재귀 DFS는 깊이가 최악 V라 파이썬 기본 한도(1,000)를 넘을 수 있습니다 → `sys.setrecursionlimit` 또는 명시적 스택.
    *   BFS는 **큐에 넣을 때** 방문 표시해야 같은 정점이 두 번 들어가지 않습니다.
    *   `list.pop(0)`은 O(N) → `deque.popleft()`는 O(1).
*   **실무 연결(윤형섭)**: OS 데드락 탐지(Wait-For Graph 사이클), GC Mark & Sweep(루트에서 도달 가능한 객체만 생존), Git 커밋 히스토리·빌드 의존성(DAG), 네트워크 STP(스패닝 트리로 루프 방지).

### 🌐 네트워크: HTTP 1.1 vs 2.0 vs 3.0 (김영웅, 조수연, 최묘석 발표)

*   **흐름**: 3회차(TCP vs UDP) → 4회차(TLS) → 5회차(HTTP 버전)로 이어졌습니다. 각 버전은 앞 버전의 병목을 하나씩 풀어 왔습니다.

| 버전 | 핵심 기술 | 개선하려는 문제 |
| :---: | :--- | :--- |
| HTTP/1.1 | 지속 연결(Keep-Alive), 파이프라이닝 | 요청마다 TCP 연결을 새로 맺는 비용 |
| HTTP/2 | 다중화, 이진 프레이밍, HPACK, 서버 푸시 | 응답 순서 대기, 중복 헤더 |
| HTTP/3 | QUIC(UDP 기반), 독립 스트림, TLS 1.3 통합 | TCP 수준 HOL Blocking, 연결 설정 지연 |

*   **HTTP/1.1**: 연결을 재사용하지만 한 연결에서 응답이 순서대로 와야 해서, 앞 응답이 늦으면 뒤가 막히는 **HOL(Head-of-Line) Blocking**이 생깁니다. 브라우저는 연결을 여러 개 열어 우회하지만 관리 비용이 남습니다.
*   **HTTP/2**: 메시지를 **프레임**으로 쪼개고 Stream ID로 구분해 하나의 연결에서 여러 요청을 섞어 보냅니다(다중화). 반복되는 헤더는 HPACK으로 압축합니다.
*   **HTTP/2에도 남는 HOL Blocking**: HTTP 레벨에서는 해결했지만 아래의 TCP는 바이트 순서를 지켜야 해서, 패킷 하나가 손실되면 **모든 스트림이 재전송을 기다립니다.**
*   **HTTP/3 (QUIC)**: UDP 위에 신뢰성·스트림을 직접 구현해 **스트림별로 독립 전송**합니다. 한 스트림의 손실이 다른 스트림을 막지 않습니다. TLS 1.3을 통합해 연결 설정 왕복이 줄고, 헤더 압축은 QPACK을 씁니다.

| 비교 | HTTP/1.1 | HTTP/2 | HTTP/3 |
| :---: | :---: | :---: | :---: |
| 전송 기반 | TCP | TCP | UDP 기반 QUIC |
| 다중화 | 미지원 | 지원 | 지원 |
| 메시지 | 텍스트 | 이진 프레임 | QUIC 스트림 프레임 |
| 헤더 압축 | 없음 | HPACK | QPACK |
| HOL Blocking | 응답 순서 문제 | TCP 수준에서 발생 | 스트림 간 해결 |
| 연결 설정 | TCP (+ TLS) | TCP + TLS | QUIC과 TLS 통합 |

### 💬 핵심 질문 정리

*   미로의 최단 경로는 왜 DFS가 아니라 BFS로 구하나? → BFS는 거리 0, 1, 2… 순으로 꺼내므로 처음 도달한 경로가 가장 짧습니다. DFS가 먼저 찾은 길은 최단이라는 보장이 없습니다.
*   가중치가 있다면? → 0/1이면 0-1 BFS, 양수면 다익스트라, 음수가 있으면 벨만-포드. **6회차 최단 경로로 이어집니다.**
*   넓고 얕은 그래프에서 메모리를 더 쓰는 쪽은? → BFS. 한 레벨이 통째로 큐에 들어갑니다.
*   HTTP/3은 왜 신뢰성 없는 UDP 위에 만들었나? → TCP는 OS 커널에 박혀 있어 바꾸기 어렵고 바이트 순서 보장 때문에 HOL Blocking이 생깁니다. UDP 위에서 필요한 신뢰성만 스트림 단위로 직접 구현한 것이 QUIC입니다.
*   HTTP/2에서도 남는 HOL Blocking은? → TCP 레벨의 HOL Blocking. 패킷 하나 손실에 모든 스트림이 대기합니다.

### 🗂️ DS: 최단 경로 알고리즘 / MST

*   **최단 경로**: 5회차 BFS는 간선 비용이 모두 같을 때만 최단 거리를 보장합니다. 비용이 다르면 다른 알고리즘이 필요합니다.
    *   **Dijkstra**: 한 시작점에서 모든 정점까지. 음수 간선 불가, 우선순위 큐(4회차 Heap) 사용 시 O(E log V).
    *   **Bellman-Ford**: 음수 간선 허용, 음수 사이클 탐지 가능. O(VE).
    *   **Floyd-Warshall**: 모든 정점 쌍의 최단 거리. O(V³).
*   **MST (최소 신장 트리)**: 모든 정점을 사이클 없이 V-1개 간선으로 잇되, 가중치 합이 최소인 트리입니다.
    *   **Kruskal**: 간선을 가중치 순으로 정렬해 사이클이 안 생기면 추가(Union-Find).
    *   **Prim**: 한 정점에서 시작해 가장 싼 간선으로 트리를 넓힘(우선순위 큐).
*   **예상 질문**: 다익스트라는 왜 음수 간선에서 틀리나요? Kruskal과 Prim은 각각 언제 유리한가요?

### 🌐 NW: DNS 동작 원리 / 브라우저에 URL 입력 시 흐름

*   **DNS**: 도메인을 IP로 바꿉니다. 브라우저 캐시 → OS(hosts) → Local DNS 서버 → Root → TLD(.com) → Authoritative 순으로 조회합니다.
*   **URL 입력 후 화면까지**: DNS로 IP 획득 → TCP 연결(3회차) → TLS(4회차) → HTTP 요청·응답(5회차) → 렌더링. 지금까지 배운 내용을 한 흐름으로 묶는 회차입니다. (2회차 전체 흐름 개요와 연결)
*   **예상 질문**: DNS는 왜 주로 UDP를 쓰나요? 재귀 쿼리와 반복 쿼리의 차이는? URL을 입력하고 엔터를 치면 어떤 일이 일어나나요?
