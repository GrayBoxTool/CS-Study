## 1. 개요 및 정의
> 이 기술/개념이 무엇이고 왜 등장했는지 간략히 서술합니다.

- 개념 정의:
  - **OSI 7 계층 (Open Systems Interconnection Reference Model)**: 네트워크 통신 과정을 **7개의 계층으로 나눠 정의한 참조 모델**. ISO가 표준화(**ISO/IEC 7498-1**)했다.
  - 각 계층은 **자신의 바로 위/아래 계층과만** 인터페이스로 소통하며, 맡은 역할만 책임진다.
- 등장 배경 및 해결하고자 한 문제:
  - 1970~80년대에는 IBM SNA, DEC DECnet 등 **벤더마다 독자 네트워크 구조**를 써서 서로 다른 제조사 장비끼리 통신이 어려웠다.
  - 통신 과정을 **계층화·표준화**하면 ① 서로 다른 시스템 간 **상호운용성**, ② 문제 발생 시 **해당 계층만 분석/교체/수정**(독립성), ③ 복잡한 통신을 **단순한 역할 단위로 분해**해 이해·설계·교육 가능.
  - ISO 표준 소개 문서 기준으로 이 모델은 *시스템 상호 접속 표준 개발을 위한 공통 기반*을 제공하고, 기존 표준들의 위치를 정리하는 것이 목적이며 **구현 명세서로 의도된 것은 아니다.**

## 2. 핵심 동작 원리 및 특징
> 개념의 핵심 로직, 구조, 동작 흐름을 시각 자료나 표, 불릿 포인트로 정리합니다.

### 2-1. 7계층 한눈에 보기 (위 → 아래)

| 계층 | 이름 | 핵심 역할 | 전송 단위 (PDU) | 대표 프로토콜 / 기술 | 대표 장비 |
| :---: | :--- | :--- | :---: | :--- | :--- |
| 7 | **응용 (Application)** | 사용자가 쓰는 앱이 네트워크를 이용하는 접점, 서비스 제공 | Data (메시지) | HTTP, HTTPS, FTP, SMTP, DNS, SSH | L7 스위치, 게이트웨이, 방화벽(WAF) |
| 6 | **표현 (Presentation)** | 데이터 **형식 변환**, 인코딩/디코딩, **암호화·복호화**, 압축 | Data | JPEG, MPEG, ASCII/UTF-8, (TLS 암·복호화를 여기에 두기도 함) | - |
| 5 | **세션 (Session)** | 통신 **세션의 시작·유지·종료**, 동기화(체크포인트) | Data | NetBIOS, RPC, PPTP 등 | - |
| 4 | **전송 (Transport)** | **종단 간(End-to-End)** 통신, 세그먼트화/재조립, 흐름·오류 제어, **포트**로 프로세스 구분 | **Segment** (TCP) / **Datagram** (UDP) | TCP, UDP | L4 스위치, 로드 밸런서 |
| 3 | **네트워크 (Network)** | **IP 주소** 기반 **라우팅**(최적 경로 선택), 네트워크 간 전달 | **Packet** | IP, ICMP, ARP(2~3 사이 논쟁), OSPF, BGP | **라우터**, L3 스위치 |
| 2 | **데이터링크 (Data Link)** | **같은 네트워크 내** 노드 간 전달, **MAC 주소**, 프레임화, 오류 검출 | **Frame** | Ethernet, Wi-Fi(802.11), PPP | **스위치**, 브리지, NIC |
| 1 | **물리 (Physical)** | 비트를 **전기/광/전파 신호**로 변환해 매체로 전송 | **Bit** | 케이블(UTP), 광섬유, 무선 주파수 | 허브, 리피터, 케이블 |

> 암기 팁: 위→아래 **"All People Seem To Need Data Processing"** (Application, Presentation, Session, Transport, Network, Data link, Physical) / 아래→위 "**P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way"

### 2-2. 핵심 원리
- **원리 1 – 캡슐화(Encapsulation) / 역캡슐화(Decapsulation)**
  - 송신 측: 데이터가 **7 → 1 계층으로 내려가며** 각 계층이 자기 **헤더(필요시 트레일러)** 를 덧붙인다.
  - 수신 측: **1 → 7 계층으로 올라가며** 각 계층이 자기 헤더를 해석·제거(역캡슐화)한다.
  - Cloudflare 설명: *데이터는 송신 장치에서 7개 계층을 내려가고, 수신 장치에서 7개 계층을 올라간다.*

```text
  송신 (Sender)                                       수신 (Receiver)
 ┌───────────┐                                     ┌───────────┐
 │ 7 응용    │  [Data]                             │ 7 응용    │
 │ 6 표현    │  [Data]                             │ 6 표현    │
 │ 5 세션    │  [Data]                             │ 5 세션    │
 │ 4 전송    │  [TCP H | Data]            Segment  │ 4 전송    │  ▲ 헤더 해석·제거
 │ 3 네트워크│  [IP H | TCP H | Data]     Packet   │ 3 네트워크│  │ (역캡슐화)
 │ 2 데이터링크│[Eth H | IP H | TCP H | Data | T]  Frame │ 2 데이터링크│ │
 │ 1 물리    │  0101 0011 ... (Bit)  ═══════════▶ │ 1 물리    │
 └───────────┘          (전송 매체)                └───────────┘
   ▼ 헤더 추가(캡슐화)
```

- **원리 2 – 계층 간 독립성(추상화)**: 상위 계층은 하위 계층의 *내부 구현*을 몰라도 *서비스*만 이용한다. (예: HTTP는 Wi-Fi든 이더넷이든 신경 쓰지 않음)
- **원리 3 – 동일 계층 간 논리적 통신(Peer-to-Peer)**: 실제 데이터는 아래로 내려가 전송되지만, 논리적으로는 송신 측 N계층과 수신 측 N계층이 **같은 프로토콜로 대화**하는 것처럼 동작한다 (헤더가 그 대화의 정보).
- **원리 4 – 주소 체계가 계층마다 다름**: L2 = **MAC 주소**(같은 링크 내 식별), L3 = **IP 주소**(네트워크 간 식별), L4 = **포트 번호**(프로세스 식별).
- **원리 5 – OSI는 "참조 모델"이다**: 실제 인터넷은 OSI 7계층 그대로 구현되지 않고 **TCP/IP 프로토콜 스위트**를 따른다. Cloudflare도 현대 인터넷이 OSI를 엄격히 따르지 않고 더 단순한 인터넷 프로토콜 스위트에 가깝지만, **트러블슈팅에 유용한 개념 모델**이라고 설명한다. (TCP/IP 4계층은 별도 문서 참고)

### 2-3. 비교 분석 표 (OSI 7계층 vs TCP/IP 4계층 – 간단 비교)

| 구분 | OSI 7 계층 | TCP/IP 4 계층 |
| :--- | :--- | :--- |
| 성격 | **이론적 참조 모델** (ISO 표준, 구현 명세 아님) | **실제 인터넷에서 쓰이는 프로토콜 스위트** (RFC로 정의) |
| 계층 수 | 7 | 4 (응용 / 전송 / 인터넷 / 링크) |
| 5·6·7 계층 | 세션·표현·응용으로 분리 | **응용 계층 하나로 통합** (RFC 1122는 응용 계층을 세분하지 않음) |
| 1·2 계층 | 물리 / 데이터링크 분리 | **링크(네트워크 인터페이스) 계층 하나로 통합** |
| 엄격한 계층화 | 계층 간 역할 구분 강조 | RFC 1122도 *"strict layering is an imperfect model"* 이라고 언급 |
| 활용 | 설명·교육·장애 분석(트러블슈팅)·장비 분류(L2/L3/L4/L7) | 실제 구현·통신 |

## 3. 실무 / 면접 핵심 포인트
> 면접관이 자주 묻는 꼬리 질문과 이에 대한 명쾌한 답변을 정리합니다.

### Q1. OSI 7계층을 나눈 이유는 무엇인가요?
- **A**: ① 통신 흐름을 **표준화**해 서로 다른 제조사·시스템끼리 호환되게 하고, ② 문제가 생기면 **해당 계층만 독립적으로 분석·수정**할 수 있으며(예: 물리 계층 케이블 교체가 응용에 영향 없음), ③ 복잡한 통신을 역할별로 **분해**해 설계·학습·장애 진단을 쉽게 하기 위해서입니다.

### Q2. 각 계층의 역할과 대표 프로토콜, 전송 단위(PDU)는 무엇인가요?
- **A**: 위 표 참고. 요약하면 **L1 비트(Bit)/L2 프레임(Frame)/L3 패킷(Packet)/L4 세그먼트(Segment, UDP는 데이터그램)/L5~7 데이터(Data)** 이고, 프로토콜은 L2 Ethernet·Wi-Fi, L3 IP·ICMP, L4 TCP·UDP, L7 HTTP·FTP·SMTP·DNS가 대표적입니다.

### Q3. 캡슐화/역캡슐화란?
- **A**: 송신 시 상위 → 하위로 내려가며 각 계층이 **헤더를 붙이는 것**이 캡슐화, 수신 시 하위 → 상위로 올라가며 **헤더를 해석하고 벗기는 것**이 역캡슐화입니다. 예: HTTP 데이터 → (TCP 헤더) 세그먼트 → (IP 헤더) 패킷 → (Ethernet 헤더·트레일러) 프레임 → 비트.

### Q4. 스위치, 라우터, 허브는 몇 계층 장비인가요? / L4, L7 스위치는?
- **A**: 허브·리피터는 **L1**, 스위치(브리지)는 MAC 주소를 보는 **L2**, 라우터는 IP 주소로 경로를 정하는 **L3**입니다. **L4 스위치**는 IP + **포트(TCP/UDP)** 정보로, **L7 스위치**는 **HTTP URL·헤더·쿠키 등 애플리케이션 데이터**까지 보고 트래픽을 분산합니다. (참고: Cloudflare 문서도 HTTP/DNS=L7, TCP/UDP=L4, IP=L3로 서비스를 계층에 매핑)

### Q5. TCP/UDP는 몇 계층이고, IP와 MAC 주소는 각각 어느 계층의 주소인가요?
- **A**: TCP/UDP는 **L4(전송)**, IP 주소는 **L3(네트워크)**, MAC 주소는 **L2(데이터링크)** 입니다. 같은 네트워크 안에서는 MAC으로, 다른 네트워크로 가려면 IP로 목적지를 찾고 라우터를 거칩니다.

### Q6. 브라우저에서 URL을 입력하면 OSI 관점에서 어떻게 흘러가나요? (간단 버전)
- **A**: L7에서 HTTP 요청 생성(DNS로 IP 조회) → L4에서 TCP 세그먼트(포트 80/443)로 분할 → L3에서 IP 패킷(출발/목적 IP) → L2에서 이더넷 프레임(다음 홉 MAC, ARP로 조회) → L1에서 비트 전송. 중간 라우터는 L3까지만 보고 재전송하며, 서버에서 역순으로 올라가 HTTP 응답을 처리합니다.

### Q7. TLS(HTTPS의 암호화)는 OSI 몇 계층인가요?
- **A**: **딱 떨어지게 정해져 있지 않습니다.** 암호화·복호화는 표현 계층(L6)의 역할로 설명되고, 세션 수립 성격은 L5, 전송 위에서 동작하는 점은 L4와 L7 사이로 보기도 합니다. TLS는 OSI가 아니라 TCP/IP 스위트 위에서 설계됐기 때문에 OSI의 어느 한 계층에 깔끔하게 대응하지 않는다고 설명하는 것이 안전합니다.

### Q8. (꼬리) 그럼 왜 실제로는 OSI가 아니라 TCP/IP를 쓰나요?
- **A**: TCP/IP는 **먼저 실제로 구현·보급**되었고(인터넷의 표준 프로토콜), OSI는 이론 모델 중심으로 구현·상용화가 따라오지 못했습니다. 그래서 OSI는 **개념 모델/공용어**, TCP/IP는 **실제 구현**으로 역할이 나뉘었습니다. 지금도 장애 분석·장비 분류·보안 이야기에서 "L2 문제", "L7 공격" 같은 OSI 용어를 씁니다.
