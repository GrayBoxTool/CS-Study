## 1. 개요 및 정의

> 네트워크 통신의 기본 개념을 이해하고, OSI 7계층과 TCP/IP 4계층의 구조 및 역할을 정리.

### 네트워크와 프로토콜

- **네트워크(Network)**: 여러 컴퓨터나 장치가 연결되어 데이터를 주고받을 수 있는 환경이다.

- **프로토콜(Protocol)**: 서로 다른 장치가 통신하기 위해 지켜야 하는 규칙이다. 데이터를 어떤 형식으로 주고받을지, 오류가 발생하면 어떻게 처리할지 등을 정의한다.

- **TCP/IP**: 인터넷 통신에서 사용되는 프로토콜들의 집합이다. TCP와 IP뿐만 아니라 UDP 등 여러 프로토콜이 포함된다.

### TCP와 IP의 차이

TCP/IP라는 이름 때문에 처음에는 하나의 프로토콜이라고 생각했지만, TCP와 IP는 서로 다른 역할을 담당한다.

- **TCP(Transmission Control Protocol)**: 데이터를 신뢰성 있게 전달하기 위한 프로토콜이다. 연결 설정, 데이터 순서 관리, 재전송, 흐름제어 등의 기능을 수행한다.

- **IP(Internet Protocol)**: IP 주소를 이용해 데이터를 목적지까지 전달하는 프로토콜이다. 패킷 전달을 담당하지만, 데이터가 반드시 도착하거나 순서대로 도착하는 것은 보장하지 않는다.

즉, **IP는 데이터를 어디로 보낼지**, **TCP는 데이터를 어떻게 신뢰성 있게 전달할지**에 초점을 맞춘다.

### OSI 7계층과 TCP/IP 4계층

- **OSI 7계층**: 네트워크 통신 과정을 7개의 계층으로 구분한 참조 모델이다.

- **TCP/IP 4계층**: 인터넷에서 사용되는 프로토콜들을 기능에 따라 4개의 계층으로 구분한 모델이다.

계층을 구분하면 각 기능의 역할을 이해하기 쉽고, 문제가 발생했을 때 어느 단계에서 오류가 발생했는지 파악하는 데 도움이 된다.

## 2. 핵심 동작 원리 및 특징

### 2-1. 네트워크 통신의 기본 용어

계층별 역할을 이해하기 위해 자주 등장하는 용어부터 정리했다.

| 용어              | 의미                                                                                   |
| :---------------- | :------------------------------------------------------------------------------------- |
| IP 주소           | 네트워크에서 통신할 장치를 식별하고 목적지로 데이터를 전달하는 데 사용하는 논리적 주소 |
| MAC 주소          | 네트워크 인터페이스를 식별하는 링크 계층 주소                                          |
| 포트(Port)        | 한 장치에서 통신할 애플리케이션을 구분하는 번호                                        |
| 헤더(Header)      | 데이터 전달에 필요한 주소, 포트, 순서 번호 등의 제어 정보                              |
| 세그먼트(Segment) | TCP에서 사용하는 데이터 전송 단위                                                      |
| 패킷(Packet)      | 네트워크에서 전달되는 데이터 단위로, 특히 IP 계층에서 자주 사용하는 표현               |
| 프레임(Frame)     | 데이터 링크 계층에서 사용하는 데이터 전송 단위                                         |
| ACK               | 데이터를 받았다는 사실을 알리는 확인 응답                                              |

IP 주소와 MAC 주소는 모두 통신에 필요한 주소이지만 역할이 다르다.

IP 주소는 여러 네트워크를 거쳐 목적지로 데이터를 전달할 때 사용하고, MAC 주소는 주로 같은 링크에서 프레임을 전달할 때 사용한다.

또한 **헤더**는 데이터 자체가 아니라 데이터를 전달하고 관리하는 데 필요한 정보를 담고 있다.

### 2-2. OSI 7계층의 구조

OSI 모델은 네트워크 통신을 7개의 계층으로 구분한다.

![OSI 7계층 모델](https://s7280.pcdn.co/wp-content/uploads/2018/06/osi-model-7-layers-1.png)

**OSI 7계층의 영문 명칭과 역할**

| 계층           | 영문 명칭    | 주요 역할                            | 관련 프로토콜 및 장비 |
| :------------- | :----------- | :----------------------------------- | :-------------------- |
| 7. 응용        | Application  | 사용자에게 네트워크 서비스 제공      | HTTP, FTP, DNS        |
| 6. 표현        | Presentation | 데이터 형식 변환, 압축, 암호화       | JPEG, MPEG            |
| 5. 세션        | Session      | 통신 세션의 설정과 관리              | 세션 관리 기능        |
| 4. 전송        | Transport    | 애플리케이션 간 데이터 전송          | TCP, UDP              |
| 3. 네트워크    | Network      | 경로 선택 및 패킷 전달               | IP, 라우터            |
| 2. 데이터 링크 | Data Link    | MAC 주소 기반 프레임 전달, 오류 검출 | 스위치, 브리지        |
| 1. 물리        | Physical     | 비트를 실제 신호로 전송              | 케이블, 허브, 리피터  |

**하위 계층부터 살펴본 주요 특징**

**1계층 - 물리 계층(Physical Layer)**

데이터를 전기적 신호 등의 형태로 변환하여 전송하는 계층이다.

케이블, 허브, 리피터 등이 관련되며 데이터를 실제로 전달하는 역할을 담당한다.

**2계층 - 데이터 링크 계층(Data Link Layer)**

같은 링크에서 데이터를 전달하는 역할을 담당한다.

MAC 주소를 이용해 프레임을 전달하며, 오류 검출 등의 기능을 수행한다. 대표적인 장비로 스위치와 브리지가 있다.

**3계층 - 네트워크 계층(Network Layer)**

IP 주소를 이용해 목적지까지 데이터를 전달한다.

라우터를 통해 패킷이 이동할 경로를 선택하는 **라우팅(Routing)** 기능이 중요하다.

**4계층 - 전송 계층(Transport Layer)**

TCP와 UDP를 이용해 애플리케이션 간 데이터 전송을 담당한다.

- **TCP**: 연결 지향적이며 신뢰성 있는 데이터 전송을 지원
- **UDP**: 비연결형 프로토콜로, TCP와 같은 재전송 및 순서 보장 기능을 기본적으로 제공하지 않음

**5계층 - 세션 계층(Session Layer)**

통신에 필요한 논리적 연결을 설정하고 관리하는 역할이다.

**6계층 - 표현 계층(Presentation Layer)**

데이터의 표현 형식을 처리하며, 인코딩, 압축, 암호화 등의 기능과 관련된다.

**7계층 - 응용 계층(Application Layer)**

사용자와 가장 가까운 계층으로, HTTP, FTP, DNS 등의 프로토콜을 통해 네트워크 서비스를 제공한다.

### 2-3. TCP/IP 4계층과 OSI 7계층 비교

TCP/IP 모델은 인터넷에서 사용되는 프로토콜들을 4개의 계층으로 분류한다.

| TCP/IP 4계층         | 대응하는 OSI 계층 | 주요 역할                     |
| :------------------- | :---------------- | :---------------------------- |
| 응용 계층            | 응용·표현·세션    | HTTP, DNS 등 응용 서비스      |
| 전송 계층            | 전송              | TCP, UDP를 이용한 데이터 전송 |
| 인터넷 계층          | 네트워크          | IP 주소 기반 패킷 전달        |
| 네트워크 액세스 계층 | 데이터 링크·물리  | 프레임 전달 및 물리적 전송    |

OSI 7계층은 네트워크 기능을 세부적으로 구분하고, TCP/IP 4계층은 실제 인터넷 프로토콜을 중심으로 구분한다는 차이가 있다.

두 모델은 계층의 수가 다르지만, 네트워크 통신을 여러 단계의 기능으로 나누어 설명한다는 공통점이 있다.

### 2-4. 데이터 전송 과정과 캡슐화

웹 브라우저에서 서버로 데이터를 보내는 상황을 통해 계층별 동작을 정리했다.

**캡슐화(Encapsulation)**는 상위 계층에서 전달받은 데이터에 하위 계층의 헤더 등을 추가하는 과정이다.

일반적인 TCP 기반 HTTP 통신을 예로 들면 다음과 같다.

1. **응용 계층**: HTTP 요청 메시지 생성
2. **전송 계층**: TCP 헤더를 추가하여 세그먼트 구성
3. **인터넷 계층**: IP 헤더를 추가하여 패킷 구성
4. **네트워크 액세스 계층**: 프레임으로 구성하여 실제 네트워크로 전송

```text
[HTTP 데이터]
      ↓
[TCP 헤더 | HTTP 데이터]
      ↓
[IP 헤더 | TCP 세그먼트]
      ↓
[프레임 헤더 | IP 패킷 | 프레임 트레일러]
```

각 계층에서 데이터에 필요한 제어 정보가 추가되므로, 같은 데이터를 계층에 따라 세그먼트, 패킷, 프레임 등으로 구분하여 부른다.

수신 측에서는 반대로 헤더 등을 확인하고 제거하는 **역캡슐화(Decapsulation)**가 이루어진다.

### 2-5. TCP의 연결 설정과 해제

TCP는 데이터를 전송하기 전에 연결을 설정하고, 통신이 끝나면 연결을 해제한다.

**3-Way Handshake - 연결 설정**

![TCP 3-Way Handshake](https://media.geeksforgeeks.org/wp-content/uploads/TCP-connection-1.png)

**이미지의 주요 영어 용어**

- **Client / Server**: 클라이언트 / 서버
- **SYN(Synchronize)**: 연결 설정 요청 및 초기 순서 번호 동기화
- **ACK(Acknowledgment)**: 수신 확인
- **Sequence Number**: 데이터의 순서를 관리하기 위한 번호
- **Established**: 연결이 성립된 상태

**연결 설정 과정**

1. 클라이언트가 서버에 **SYN** 전송
2. 서버가 클라이언트에 **SYN + ACK** 전송
3. 클라이언트가 서버에 **ACK** 전송

세 번의 메시지 교환이 완료되면 TCP 연결이 성립된다.

**4-Way Handshake - 연결 해제**

![TCP 4-Way Handshake](https://media.geeksforgeeks.org/wp-content/uploads/CN.png)

연결을 종료할 때는 **FIN(Finish)** 플래그를 사용한다.

1. 클라이언트가 서버에 FIN 전송
2. 서버가 ACK로 응답
3. 서버가 남은 데이터 전송을 마친 후 FIN 전송
4. 클라이언트가 ACK로 응답

연결 해제 과정에서 등장하는 상태는 다음과 같다.

- **CLOSE_WAIT**: 상대방의 종료 요청을 받은 뒤 자신의 연결 종료를 준비하는 상태
- **TIME_WAIT**: 마지막 ACK를 보낸 측이 일정 시간 연결 정보를 유지하는 상태

### 2-6. TCP의 흐름제어와 혼잡제어

TCP는 데이터가 안정적으로 전달될 수 있도록 전송량을 조절한다.

**흐름제어(Flow Control)**

송신 측과 수신 측의 데이터 처리 속도 차이를 해결하기 위한 기능이다.

수신 측의 처리 속도보다 송신 측의 전송 속도가 빠르면 수신 버퍼가 넘칠 수 있으므로 전송량을 조절해야 한다.

- **Stop and Wait**: 데이터를 보낸 뒤 ACK를 받을 때까지 다음 전송을 기다리는 방식
- **Sliding Window**: 일정 범위의 데이터를 ACK를 기다리지 않고 연속해서 전송하는 방식

Sliding Window에서는 수신 측이 처리할 수 있는 데이터의 양을 나타내는 **수신 윈도우(Receive Window)**가 중요하다.

**혼잡제어(Congestion Control)**

네트워크에 패킷이 과도하게 몰리는 상황을 방지하기 위한 기능이다.

흐름제어가 수신 측의 처리 능력을 고려한다면, 혼잡제어는 네트워크의 혼잡 상태를 고려한다.

대표적인 방식은 다음과 같다.

- **AIMD**: 혼잡이 없으면 전송량을 조금씩 늘리고, 혼잡이 발생하면 크게 줄이는 방식
- **Slow Start**: 초기 전송량을 빠르게 증가시키는 방식
- **Fast Retransmit**: 중복 ACK를 이용해 손실이 의심되는 데이터를 빠르게 재전송하는 방식
- **Fast Recovery**: 손실 감지 이후 전송량을 조절하며 회복하는 방식

이러한 방식은 TCP의 대표적인 혼잡제어 원리를 설명하며, 실제 구현에서는 사용하는 혼잡제어 알고리즘에 따라 동작이 달라질 수 있다.

## 3. 실무 / 면접 핵심 포인트

### Q1. OSI 7계층과 TCP/IP 4계층의 차이점을 설명하시오.

- **A**: OSI 7계층은 네트워크 통신 기능을 7개로 세분화한 참조 모델이고, TCP/IP 4계층은 인터넷에서 사용되는 프로토콜들을 4개의 계층으로 구분한 모델입니다.

  TCP/IP 모델에서는 OSI의 응용·표현·세션 계층을 응용 계층으로 묶고, 데이터 링크·물리 계층을 네트워크 액세스 계층으로 묶어 설명합니다.

### Q2. TCP와 IP의 역할이 어떻게 다른지 설명하시오.

- **A**: IP는 IP 주소를 이용해 데이터를 목적지까지 전달하는 역할을 담당합니다. 하지만 패킷이 반드시 도착하거나 순서대로 도착하는 것은 보장하지 않습니다.

  TCP는 연결 설정, 순서 관리, 재전송, 흐름제어 등을 통해 신뢰성 있는 데이터 전달을 지원합니다.

### Q3. 패킷과 세그먼트의 차이점을 설명하시오.

- **A**: 세그먼트는 TCP 전송 계층에서 사용하는 데이터 단위이고, IP 패킷은 인터넷 계층에서 사용하는 데이터 단위입니다.

  일반적으로 TCP 세그먼트에 IP 헤더가 추가되면 IP 패킷이 됩니다. 이러한 과정을 캡슐화라고 합니다.

### 계층 모델을 구분하는 이유

네트워크 통신을 계층별로 구분하면 각 기능의 역할을 이해할 수 있을 뿐 아니라, 문제가 발생했을 때 원인을 단계적으로 분석할 수 있다.

예를 들어 웹사이트에 접속되지 않는 상황에서도 원인은 다양할 수 있다.

- **물리 계층**: 케이블 연결이나 무선 신호 문제
- **네트워크 계층**: IP 주소 설정이나 라우팅 문제
- **전송 계층**: TCP 연결 실패 또는 포트 접근 문제
- **응용 계층**: HTTP 요청 처리 과정에서 발생한 오류

이처럼 같은 접속 오류라도 문제가 발생한 계층에 따라 확인해야 할 부분이 달라진다.

### 학습하며 느낀 점

처음에는 TCP/IP가 하나의 프로토콜인지, TCP와 IP가 각각 어떤 역할을 하는지 명확하게 구분하지 못했다. 이번 학습을 통해 TCP/IP는 여러 프로토콜을 포함하는 개념이고, TCP와 IP는 서로 다른 계층에서 동작한다는 점을 이해했다.

또한 MAC 주소, IP 주소, 포트 번호가 모두 통신에 사용되는 정보이지만 각각 담당하는 역할이 다르다는 점을 알게 되었다.

특히 캡슐화 과정을 정리하면서 데이터가 네트워크를 통해 전달될 때 단순히 내용만 전송되는 것이 아니라, 각 계층에서 필요한 헤더가 추가된다는 점이 인상적이었다.

OSI 7계층과 TCP/IP 4계층을 단순히 암기하기보다 HTTP, TCP, IP 등의 프로토콜이 어떤 계층에 속하고 서로 어떻게 연결되는지 이해하는 것이 중요하다고 느꼈다.
