# 📑 TCP/IP 4계층 — 와이파이는 연결됐는데 인터넷은 왜 안 될까?

> **발표자**: 최나현  
> **날짜**: 2026.11.04.
> **카테고리**: Network  
> **참고 링크**: [RFC 1122 — 인터넷 통신 계층](https://www.rfc-editor.org/rfc/rfc1122)

---

## 1. 개요 및 정의

- **개념 정의**: TCP/IP 4계층은 인터넷 통신에 필요한 기능을 **응용·전송·인터넷·링크**라는 네 가지 역할로 나누어 설명하는 모델이다. 이름에 TCP와 IP가 들어가지만 HTTP, DNS, UDP 등 다양한 프로토콜이 함께 사용된다.
- **등장 배경 및 해결하고자 한 문제**: 서로 다른 장치와 네트워크가 통신하려면 공통 규칙이 필요하다. 웹 요청 내용 만들기부터 실제 신호 전송까지 역할을 나누면 다양한 기술을 조합하기 쉽고, 문제가 발생했을 때 원인을 단계별로 살펴볼 수 있다.
- **주제를 이해할 출발점**: 와이파이 표시가 떠 있는데 웹사이트가 열리지 않는 경험이 있다. 와이파이 연결은 휴대폰과 무선 접속 장치 사이의 연결이며, 멀리 있는 웹 서버까지 통신할 수 있다는 보장은 아니다.

---

## 2. 핵심 동작 원리 및 특징

### 2-1. 네 계층이 맡는 역할

| 계층 | 쉽게 이해할 질문 | 핵심 역할 | 대표 예시 |
| :--- | :--- | :--- | :--- |
| 응용(Application) | 무엇을 주고받을까? | 서비스에서 사용하는 메시지 형식과 통신 규칙을 다룬다. | HTTP, DNS |
| 전송(Transport) | 어느 앱의 통신이며 어떻게 전달할까? | 포트로 통신 종단을 구분하고, 프로토콜에 따라 전달 기능을 제공한다. | TCP, UDP |
| 인터넷(Internet) | 목적지까지 어떻게 보낼까? | IP 주소와 라우팅 정보를 바탕으로 네트워크 사이에서 패킷을 전달한다. | IP |
| 링크(Link) | 바로 연결된 구간에서 어떻게 보낼까? | 해당 구간의 유선·무선 기술로 데이터를 전달한다. | Wi-Fi, Ethernet |

링크 계층은 **네트워크 인터페이스 계층** 또는 **네트워크 접근 계층**이라고도 부른다. 계층은 역할을 이해하는 기준이며, 실제 구현의 모든 기능이 정확하게 나뉜다는 뜻은 아니다.

### 2-2. 와이파이는 링크 계층에 해당한다

집에서 휴대폰을 와이파이에 연결하면, 휴대폰과 공유기의 무선 접속 기능 사이에서 데이터를 주고받을 수 있다. 가정용 공유기는 일반적으로 무선 접속 기능과 라우팅 기능 등을 함께 제공한다.

다만 **휴대폰에서 공유기까지 연결된 것**과 **인터넷을 거쳐 서버까지 통신하는 것**은 다르다. 공유기 바깥 회선이 끊겼거나 주소 설정 등에 문제가 있으면 와이파이 표시가 있어도 웹사이트가 열리지 않을 수 있다.

### 2-3. 예시: 와이파이로 웹사이트를 여는 과정

설명을 위해 **TCP를 사용하는 HTTPS 통신**을 예로 든다. DNS 조회와 연결 설정 등의 준비 과정이 있지만, 여기서는 연결이 준비된 뒤 요청 데이터가 전달되는 역할에 집중한다.

1. **응용 계층 — 요청 내용 만들기**  
   브라우저가 “이 페이지를 보내주세요”에 해당하는 HTTP 요청을 만든다. HTTPS에서는 HTTP 데이터를 보호하기 위한 암호화도 적용된다.
2. **전송 계층 — 앱 사이에서 전달하기**  
   TCP가 포트 번호로 통신 종단을 구분하고, 데이터의 순서를 관리하며 손실 시 재전송한다. 연결을 복구할 수 없으면 전송이 실패할 수도 있다.
3. **인터넷 계층 — 목적지 IP를 향해 보내기**  
   IP 패킷에 목적지 주소가 들어간다. 라우터들은 목적지와 라우팅 정보를 보고 다음 전달 방향을 선택한다.
4. **링크 계층 — 현재 구간을 실제로 건너기**  
   휴대폰에서 공유기의 무선 접속 기능까지는 와이파이로 전달한다. 그 이후 구간에서는 Ethernet 등 다른 기술을 사용할 수 있다.
5. **수신 측에서 해석하기**  
   서버는 각 계층의 정보를 처리하여 요청을 해석한다. 응답 역시 계층별 기능을 거쳐 휴대폰으로 전달된다.

> 네 계층이 서로 다른 네 장소라는 뜻은 아니다. 송신 장치 안에서도 여러 계층의 처리가 이루어지고, 링크 전달은 경로의 각 구간에서 반복된다. 또한 HTTP/3은 QUIC/UDP를 사용하므로 모든 웹 통신이 TCP를 거치는 것은 아니다.

### 2-4. 캡슐화와 역캡슐화

**캡슐화**는 데이터를 보내면서 각 계층이 전달에 필요한 정보를 덧붙이는 과정이다. 받는 쪽이 그 정보를 해석하며 안쪽 데이터를 처리하는 역과정을 **역캡슐화**라고 한다.

| 정보 | 사용 목적 |
| :--- | :--- |
| TCP의 포트·순서 정보 | 통신 종단 구분과 순서 관리 |
| IP의 출발지·목적지 주소 | 네트워크 사이에서 패킷 전달 |
| 링크의 주소·제어 정보 | 해당 링크 구간에서 프레임 전달 |

HTTP 요청 하나가 반드시 TCP 세그먼트 하나 또는 IP 패킷 하나가 되는 것은 아니다.

### 2-5. 생활 속 상황에 적용하기

| 상황 | 생각해 볼 원인 | 해석할 때 주의할 점 |
| :--- | :--- | :--- |
| 와이파이 자체가 연결되지 않음 | 신호 세기, 무선 접속 장치, 인증 문제 | 무선 연결 과정부터 확인한다. |
| 와이파이는 연결됐지만 여러 사이트가 열리지 않음 | 외부 회선, IP 설정, DNS 등 | 와이파이 표시만으로 인터넷 연결을 판단할 수 없다. |
| 다른 사이트는 되지만 특정 사이트만 열리지 않음 | 해당 서버, DNS, 접속 제한 등 | 특정 계층의 문제라고 즉시 단정하지 않는다. |
| 사이트에서 HTTP 500 응답을 받음 | 서버 측 처리 문제 | 해당 요청에서 HTTP 응답을 받을 정도의 통신은 이루어졌다. |

계층 모델은 장애 원인을 바로 확정하는 도구가 아니라, **어떤 정보를 더 확인할지 정리하는 기준**이다.

## 3. 실무 / 면접 핵심 포인트

### Q1. 와이파이는 연결됐는데 인터넷은 왜 안 될까요?

- **A**: 휴대폰과 공유기 사이의 무선 연결이 되어 있어도 서버까지 가는 통신 전체가 정상이라는 뜻은 아니기 때문이다. 외부 회선이나 IP 설정, DNS 등에 문제가 있을 수 있다. 다른 기기와 다른 사이트에서도 같은 문제가 생기는지 비교하면 원인 범위를 좁히는 데 도움이 된다.

### Q2. 와이파이 대신 랜선을 연결하면 TCP/IP도 달라지나요?

- **A**: 링크 계층의 연결 기술이 와이파이에서 Ethernet으로 달라진다. 그 위에서는 HTTP, TCP, IP 등을 계속 사용할 수 있다. 역할을 나눠 놓으면 서로 다른 연결 기술 위에서도 같은 서비스를 이용할 수 있다.

### Q3. IP 주소와 포트 번호는 왜 둘 다 필요한가요?

- **A**: IP 주소는 네트워크에서 목적지를 찾아 전달하는 데 쓰이고, 포트는 호스트 내부의 통신 종단을 구분하는 데 쓰인다. 한 컴퓨터에서 여러 앱이 통신할 수 있으므로 목적지 주소만으로는 충분하지 않다. 실제 연결을 구분할 때는 양 끝의 주소와 포트 등을 함께 본다.

### Q4. TCP/IP라는 이름이면 TCP를 반드시 사용하나요?

- **A**: 아니다. TCP/IP는 인터넷 프로토콜 체계를 부르는 이름이다. 전송 계층에서 UDP를 사용할 수도 있다. TCP는 순서 있는 신뢰성 있는 바이트 스트림을 제공하고, UDP 자체는 전달이나 순서를 보장하지 않는 데이터그램 서비스를 제공한다.

### Q5. 계층을 나누면 어떤 점이 좋은가요?

- **A**: 복잡한 통신을 역할별로 이해하고, 정해진 인터페이스를 통해 기능을 조합하기 쉬워진다. 예를 들어 와이파이와 Ethernet처럼 링크 기술이 달라도 같은 응용 서비스를 사용할 수 있다. 다만 계층끼리 서로 영향을 주지 않는다는 뜻은 아니다.

### Q6. TCP/IP를 5계층으로 설명하는 자료도 있던데요?

- **A**: 링크 계층의 기능을 데이터링크와 물리로 나눠 다섯 계층으로 설명하기도 한다. 설명 관점의 차이다. 이번 발표에서는 응용·전송·인터넷·링크의 네 계층 모델을 기준으로 한다.
