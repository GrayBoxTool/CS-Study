## 1. 개요 및 정의

**와이파이로도, 랜선으로도 같은 웹사이트에 접속할 수 있다. 왜 그럴까?**

가까운 장치와 연결하는 방법은 달라도, 인터넷에서 데이터를 주고받는 규칙을 함께 사용할 수 있기 때문이다.

**TCP/IP 4계층**은 이 통신 과정을 **네 가지 역할**로 나누어 설명하는 모델이다.

- **TCP/IP**: 인터넷 통신에 사용하는 규칙들의 체계. TCP와 IP 외에도 여러 규칙이 포함된다.
- **프로토콜**: 장치들이 데이터를 주고받을 때 지키는 규칙.
- **계층**: 통신에 필요한 역할을 나눈 구분.

### TCP란? — 데이터를 순서대로 전달하는 규칙

**TCP(Transmission Control Protocol, 전송 제어 프로토콜)**는 양 끝의 앱이 데이터를 **순서대로, 빠진 부분 없이 전달받도록 관리하는 규칙**이다. 네 계층 중 **전송 계층**에 해당한다.

- 데이터를 보내기 전에 상대와 연결을 맺는다.
- 데이터에 순서 정보를 붙이고, 받은 쪽의 확인 응답을 활용한다.
- 중간에 빠진 데이터는 다시 보내고, 도착 순서가 바뀌면 순서에 맞춰 앱에 전달한다.

**예시:** `안녕하세요`를 보내는 상황을 생각해 보자. 데이터 일부가 늦거나 빠지더라도 TCP는 앱이 원래 순서의 데이터를 받도록 관리한다. 실제 전송이 글자 단위로 나뉜다는 뜻은 아니다.

> **기억하기: TCP는 “데이터가 제대로, 순서대로 전달되도록 관리하기”.** 연결이 끊겨 복구되지 않으면 전송이 실패할 수도 있다. TCP 자체가 데이터를 암호화하는 것은 아니다.

### IP란? — 목적지 주소를 바탕으로 전달하는 규칙

**IP(Internet Protocol, 인터넷 프로토콜)**는 **IP 주소를 사용해 여러 네트워크를 거쳐 데이터를 목적지로 전달하는 규칙**이다. 네 계층 중 **인터넷 계층**에 해당한다.

- 보내는 데이터에 출발지와 목적지 IP 주소 등을 포함한다.
- 데이터를 운반하는 단위를 **IP 패킷**이라고 한다.
- 중간의 라우터는 목적지 주소와 자신이 가진 경로 정보를 보고 다음 전달 방향을 결정한다.

**예시:** 노트북에서 멀리 있는 웹 서버로 요청을 보낼 때, 목적지 IP 주소를 바탕으로 여러 라우터를 거쳐 전달한다. IP 주소는 전달에 사용하는 주소이고, IP는 그 주소를 이용하는 통신 규칙이다.

> **기억하기: IP는 “주소를 보고 목적지 쪽으로 전달하기”.** IP 자체는 데이터의 도착이나 도착 순서를 보장하지 않는다.

### TCP와 IP를 함께 쓰면?

| 구분 | IP | TCP |
| :--- | :--- | :--- |
| 핵심 역할 | 목적지 주소를 바탕으로 패킷 전달 | 앱 사이에서 순서·손실 등을 관리 |
| 해당 계층 | 인터넷 계층 | 전송 계층 |
| 쉬운 비유 | 주소가 적힌 물건을 목적지로 운반 | 물건이 빠짐없이 왔는지 확인하고 순서대로 정리 |

**TCP 데이터를 IP 패킷에 담아 보내면, IP는 목적지 전달을 담당하고 TCP는 양 끝에서 전달 상태를 관리한다.** 두 규칙은 서로 다른 역할로 함께 작동한다.

이번 발표에서는 **연결 방식은 무엇이 다르고, 인터넷 통신에서는 무엇이 공통인지** 알아본다.

## 2. 네 계층이란 무엇인가

웹사이트를 여는 상황에 대입하면 이해하기 쉽다.

| 계층 | 맡은 역할 | 웹사이트를 열 때 |
| :--- | :--- | :--- |
| **응용** | 주고받을 내용과 형식 정하기 | 브라우저가 “이 페이지를 보내주세요”라는 요청을 만든다. |
| **전송** | 양 끝의 앱 사이에서 데이터 전달하기 | TCP가 데이터 순서를 관리하고, 빠진 데이터는 다시 보낸다. |
| **인터넷** | 목적지 주소를 보고 전달하기 | IP 주소를 바탕으로 데이터를 서버 쪽으로 보낸다. |
| **링크** | 바로 연결된 구간에서 전달하기 | 휴대폰과 공유기 사이에서 와이파이로 데이터를 보낸다. |

> **기억할 말: 내용 만들기 → 앱 사이 전달 → 목적지 찾기 → 연결된 구간 건너기**

네 계층이 네 개의 장비를 뜻하는 것은 아니다. 한 기기 안에서도 여러 계층의 처리가 이루어진다.

### 2-1. 우리가 흔히 쓰는 연결 방식은 어디에 해당하는가

와이파이·유선랜·블루투스는 제품명보다는 **연결 기술**이라고 부르면 된다.

| 연결 방식 | 익숙한 모습 | 계층과의 관계 |
| :--- | :--- | :--- |
| **와이파이** | 휴대폰을 공유기에 무선으로 연결 | 링크 계층 |
| **유선랜(Ethernet)** | PC에 랜선을 꽂아 연결 | 링크 계층 |
| **블루투스 테더링** | 휴대폰 인터넷을 노트북에 블루투스로 공유 | 노트북과 휴대폰 사이의 연결을 링크 계층 관점에서 설명 가능 |

**블루투스 이어폰과 테더링은 다르다.**

- 이어폰 연결: 소리를 전달한다.
- 테더링: 다른 기기에 인터넷 연결을 나눠준다.

여기서는 **블루투스로 인터넷을 공유하는 경우**를 다룬다. 모든 블루투스 통신이 TCP/IP를 사용하는 것은 아니다.

### 2-2. 각 연결 방식으로 웹사이트를 여는 과정

#### 먼저, 세 방식의 공통점

브라우저는 페이지를 요청하고, 서버는 그에 대한 데이터를 돌려준다. 브라우저가 받은 데이터를 해석하면 화면에 웹페이지가 나타난다.

아래는 **TCP를 사용하는 HTTPS 웹 통신**의 예시다. 주소 조회와 연결 준비는 끝났다고 가정한다.

#### 📶 ① 와이파이 — 집에서 휴대폰으로 접속

1. **응용:** 브라우저가 페이지 요청을 만든다. HTTPS이므로 데이터는 암호화되어 전달된다.
2. **전송·인터넷:** TCP가 순서 등을 관리하고, IP가 목적지 주소를 이용해 전달한다.
3. **링크:** 휴대폰에서 공유기까지 **와이파이**로 보낸다.
4. 공유기를 통해 외부 인터넷으로 나가 서버에 도착한다.
5. 서버의 응답이 돌아오면 브라우저가 페이지를 표시한다.

> **핵심: 와이파이는 휴대폰이 공유기까지 가는 연결이다. 서버까지 모든 구간이 와이파이인 것은 아니다.**

#### 🔌 ② 유선랜 — PC에 랜선을 꽂고 접속

1. PC의 브라우저가 페이지 요청을 만든다.
2. TCP와 IP가 데이터 전달을 처리한다.
3. PC에서 연결된 공유기나 스위치까지 **랜선(Ethernet)**으로 보낸다.
4. 외부 인터넷을 거쳐 서버에 도착한다.
5. 응답을 받으면 브라우저가 페이지를 표시한다.

> **핵심: 첫 연결이 와이파이에서 유선랜으로 바뀌어도, HTTP·TCP·IP 등을 계속 사용할 수 있다.**

#### 📱 ③ 블루투스 테더링 — 휴대폰 인터넷을 노트북에 공유

**상황:** 주변에 와이파이가 없고, 휴대폰에는 LTE·5G 인터넷이 된다. 두 기기는 블루투스 테더링을 지원하고 설정도 마쳤다.

1. 노트북의 브라우저가 요청을 만들고 TCP·IP로 보낼 준비를 한다.
2. 노트북이 **블루투스**로 휴대폰에 데이터를 보낸다.
3. 휴대폰이 **LTE·5G**로 외부 인터넷에 전달한다.
4. 서버의 응답이 휴대폰을 거쳐 노트북으로 돌아온다.
5. 노트북의 브라우저가 페이지를 표시한다.

> **핵심: 노트북과 휴대폰 사이는 블루투스, 휴대폰과 통신사 사이는 LTE·5G다.**

블루투스로 기기를 연결하기만 해서는 인터넷이 공유되지 않는다. **테더링 설정과 휴대폰의 외부 인터넷 연결**이 필요하다.

#### 세 방식의 차이만 한눈에 보기

| 방식 | 내 기기가 처음 데이터를 보내는 방법 | 외부 인터넷 연결 |
| :--- | :--- | :--- |
| 와이파이 | 무선으로 공유기에 전달 | 공유기에 연결된 인터넷 회선 |
| 유선랜 | 랜선으로 공유기 등에 전달 | 공유기 등에 연결된 인터넷 회선 |
| 블루투스 테더링 | 블루투스로 휴대폰에 전달 | 휴대폰의 LTE·5G |

위 표는 대표적인 사용 예시다. 실제 경유 장비와 구성은 환경에 따라 달라진다.

### 2-3. 그 밖에 알아둘 TCP/IP의 특징

#### ① 와이파이 연결과 인터넷 연결은 다르다

와이파이 표시는 휴대폰과 공유기 사이가 연결됐다는 뜻이다. 공유기 바깥 회선이 끊겨 있으면 웹사이트에 접속하지 못할 수 있다.

#### ② 데이터를 보낼 때 필요한 정보를 붙인다

택배에 배송 정보를 붙이듯, 데이터에도 전달에 필요한 정보를 붙인다.

- **전송 계층:** 어느 앱의 통신인지 구분하는 포트 번호 등
- **인터넷 계층:** 출발지와 목적지의 IP 주소
- **링크 계층:** 지금 연결된 구간에서 전달하는 데 필요한 정보

이렇게 정보를 덧붙이는 것을 **캡슐화**, 받는 쪽에서 그 정보를 해석하는 역과정을 **역캡슐화**라고 한다.

#### ③ 모든 웹 통신이 TCP를 쓰지는 않는다

이번 사례에서는 TCP를 사용했다. 다른 방식도 있으며, **HTTP/3은 QUIC/UDP를 사용한다.** TCP/IP라는 이름이 TCP만 사용한다는 뜻은 아니다.

#### ④ 연결 방식만으로 속도를 판단할 수 없다

와이파이 신호가 강해도 인터넷 회선이나 서버가 느리면 페이지가 늦게 열릴 수 있다. 연결부터 응답까지 여러 구간이 함께 영향을 준다.

## 3. 실무 / 면접 가능성이 있는 질문

### Q1. 와이파이와 유선랜이 달라도 같은 HTTP·TCP·IP를 사용할 수 있는 이유는?

**A. 연결 구간의 전달과 그 위의 통신 역할이 나뉘어 있기 때문이다.** 와이파이와 유선랜은 링크 계층의 기술이다. 이 연결 위에서 IP는 목적지 전달을, TCP는 앱 사이의 순서 있는 전달을, HTTP는 웹 요청·응답을 담당할 수 있다.

### Q2. TCP 연결은 노트북과 공유기 사이에 맺어지나요, 노트북과 웹 서버 사이에 맺어지나요?

**A. 일반적인 직접 웹 접속에서는 노트북과 웹 서버 사이에 맺어진다.** 공유기는 중간에서 패킷을 전달한다. 가정용 공유기가 주소 변환(NAT)을 하더라도 보통 웹 서버처럼 TCP 연결을 끝내지는 않는다. 다만 프록시 등이 중간에서 연결을 받아 별도 연결을 만드는 구성도 있다.

### Q3. 데이터가 여러 라우터를 지날 때 링크 계층의 전달은 어떻게 반복되나요?

**A. 경로의 각 연결 구간에서 반복된다.** 노트북에서 공유기까지는 와이파이, 다음 구간은 Ethernet을 사용할 수 있다. 라우터는 들어온 링크의 전달 정보를 처리하고, IP 목적지와 라우팅 정보를 확인한 뒤 다음 구간에 맞는 새 프레임으로 보낸다. 프레임은 해당 링크에서 데이터를 운반하는 단위다.

### Q4. IP가 목적지를 찾아준다면 TCP는 추가로 무엇을 담당하나요?

**A. TCP는 양 끝의 앱 사이에서 데이터를 순서대로 전달하고, 손실된 데이터는 다시 보낸다.** IP 자체는 도착이나 순서를 보장하지 않는다. TCP는 포트 번호로 통신 종단도 구분한다. 다만 연결을 복구할 수 없는 상황에서는 TCP 전송도 실패할 수 있다.

### Q5. 서버가 데이터를 받으면 네 계층을 어떤 순서로 처리하나요?

**A. 기본 흐름은 링크 → 인터넷 → 전송 → 응용 순서다.** 링크의 전달 정보를 확인하고 IP 정보를 처리한 다음, TCP가 데이터를 순서에 맞게 모아 응용 쪽에 전달한다. HTTPS에서는 암호화된 데이터를 복호화한 뒤 HTTP 요청을 해석한다. 보내는 쪽에서 덧붙인 정보를 받는 쪽에서 차례로 해석하는 과정을 역캡슐화라고 한다.
