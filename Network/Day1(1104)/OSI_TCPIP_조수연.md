## 1. 개요 및 정의

네트워크 통신은 애플리케이션의 데이터를 상대방에게 전달하는 과정이다. 이 과정에는 데이터 형식 결정, 프로세스 구분, 경로 선택, 같은 링크 안에서의 전달, 신호 전송 등 여러 역할이 필요하다.

**OSI 7계층**은 통신 기능을 일곱 계층으로 나눈 참조 모델이다. **TCP/IP 4계층**은 인터넷 프로토콜 구조를 설명하는 모델이다. 계층을 나누면 각 역할을 구분하기 쉽고, 문제가 발생했을 때 어느 부분을 확인해야 하는지 좁힐 수 있다.

두 모델의 계층은 정확히 일대일로 대응하지 않는다. 실제 프로토콜이나 장비가 여러 계층의 기능을 함께 수행할 수도 있다.

## 2. OSI 7계층의 역할

| 계층 | 이름 | 주요 역할 | 관련 예시 |
| --- | --- | --- | --- |
| 7 | 응용(Application) | 사용자 애플리케이션이 사용하는 통신 기능과 메시지 규칙 제공 | HTTP, DNS, SMTP |
| 6 | 표현(Presentation) | 데이터 표현 형식, 인코딩, 압축, 암호화 등 | 문자 인코딩, 직렬화, 암호화 기능 |
| 5 | 세션(Session) | 대화·세션의 수립, 유지, 종료와 동기화 | 대화 제어, 체크포인트 기능 |
| 4 | 전송(Transport) | 종단 간 전송, 포트 기반 다중화·역다중화 | TCP, UDP |
| 3 | 네트워크(Network) | 논리 주소와 네트워크 간 패킷 전달, 경로 선택 | IP, 라우터 |
| 2 | 데이터 링크(Data Link) | 같은 링크 내 프레임 전달, 링크 주소와 오류 검출 등 | Ethernet, Wi-Fi의 MAC 기능, 스위치 |
| 1 | 물리(Physical) | 비트를 전기·광·무선 신호로 전송 | 케이블, 광 신호, 무선 신호 |

### 2.1 응용·표현·세션 계층

응용 계층의 HTTP는 요청과 응답의 형식을 정의한다. 표현 계층은 데이터를 어떤 형식으로 표현할지, 세션 계층은 통신 대화를 어떻게 관리할지 설명한다.

실제 인터넷에서는 이 기능들이 라이브러리나 응용 프로토콜에 함께 구현되기도 한다. 예를 들어 TLS는 암호화와 인증 등을 제공하지만, 이를 실제 TCP/IP 구조에서 별도의 OSI 6계층 프로토콜이라고 단정하면 구조를 지나치게 단순화하게 된다.

### 2.2 전송 계층

포트 번호로 호스트 안의 통신 종단점을 구분한다. 운영체제는 프로토콜과 IP 주소, 포트 등의 정보를 이용해 데이터를 적절한 소켓으로 전달한다.

- **TCP**: 연결을 수립하고 순서 있는 바이트 스트림을 제공한다. 손실 시 재전송하며 흐름 제어와 혼잡 제어를 수행한다. 연결이 실패할 수도 있으므로 애플리케이션의 처리 완료까지 보장하는 것은 아니다.
- **UDP**: 데이터그램 단위로 전송한다. 프로토콜 자체에서 전달, 순서, 중복 제거를 보장하지 않으며 필요한 기능은 상위 계층에서 구현할 수 있다.

전송 계층 전체가 신뢰성을 보장한다고 말하면 안 된다. 제공하는 기능은 프로토콜에 따라 다르다.

### 2.3 네트워크·데이터 링크·물리 계층

- **네트워크 계층**: 목적지 IP 주소와 라우팅 정보를 바탕으로 패킷을 다음 홉으로 전달한다. IP는 최선형 전달을 제공하며 도착이나 순서를 보장하지 않는다.
- **데이터 링크 계층**: 현재 링크에서 다음 장비로 프레임을 전달한다. Ethernet에서는 MAC 주소를 사용한다. 오류 검출이 가능하더라도 모든 링크 프로토콜이 재전송을 제공하는 것은 아니다.
- **물리 계층**: 프레임을 구성하는 비트를 실제 신호로 전달한다.

## 3. TCP/IP 4계층과의 비교

| TCP/IP 모델 | 대응하는 OSI 계층 | 대표 예시 |
| --- | --- | --- |
| 응용 계층 | 응용·표현·세션 | HTTP, DNS, SMTP |
| 전송 계층 | 전송 | TCP, UDP |
| 인터넷 계층 | 네트워크 | IPv4, IPv6, ICMP |
| 링크 계층(네트워크 접근 계층) | 데이터 링크·물리 | Ethernet, Wi-Fi |

교재에 따라 링크 계층을 데이터 링크와 물리 계층으로 나눈 **5계층 모델**도 사용한다. 계층 수를 외우는 것보다 각 기능이 어떤 책임을 맡는지 이해하는 것이 중요하다.

## 4. 캡슐화와 역캡슐화

송신 측에서는 상위 계층의 데이터를 하위 계층이 자신의 데이터로 감싸고 제어 정보를 추가한다. 이를 **캡슐화**라고 한다. 수신 측에서는 정보를 해석하고 제거하면서 상위 계층으로 전달하는 **역캡슐화**가 일어난다.

TCP와 Ethernet을 사용하는 통신을 단순화하면 다음과 같다.

```text
응용 데이터
  ↓ TCP 헤더 추가
TCP 세그먼트
  ↓ IP 헤더 추가
IP 패킷
  ↓ Ethernet 헤더·트레일러 추가
Ethernet 프레임
  ↓ 신호로 전송
비트
```

TCP는 세그먼트, UDP는 데이터그램이라는 용어를 사용한다. 응용 메시지 하나가 TCP 세그먼트 하나에 반드시 대응하는 것은 아니다. TCP는 바이트 스트림이므로 메시지 경계는 애플리케이션 프로토콜이 구분해야 한다.

### 다른 네트워크의 서버로 전달할 때

1. 호스트는 라우팅 테이블을 확인해 다음 홉을 결정한다. 일반적인 외부 서버 통신에서는 기본 게이트웨이가 다음 홉이 된다.
2. Ethernet과 IPv4 환경에서 다음 홉의 MAC 주소를 모르면 ARP로 확인한다. IPv6에서는 Neighbor Discovery를 사용한다.
3. IP 패킷을 다음 홉으로 보낼 링크 프레임에 담아 전송한다.
4. 라우터는 받은 링크 프레임을 해석하고 목적지 IP와 라우팅 테이블을 바탕으로 다음 홉을 선택한다.
5. 다음 링크에 맞는 새 프레임으로 패킷을 전달한다. IPv4 TTL 또는 IPv6 Hop Limit은 홉을 지날 때 감소한다.

**외부 서버로 보낼 때 첫 Ethernet 프레임의 목적지 MAC은 보통 서버의 MAC이 아니라 게이트웨이의 MAC이다.** 링크 헤더는 홉마다 바뀐다. IP의 출발지·목적지 주소는 일반적인 라우팅에서는 유지되지만 NAT가 개입하면 바뀔 수 있다.

## 5. 웹 요청에 적용하기

HTTP/1.1 또는 HTTP/2로 HTTPS 서버에 처음 연결하는 경우를 단순화한 예시다. 캐시와 기존 연결은 없다고 가정한다.

1. DNS를 통해 도메인에 대응하는 IP 주소를 알아낸다.
2. 서버의 IP와 포트로 TCP 연결을 수립한다.
3. TLS 핸드셰이크로 인증서를 검증하고 암호화 통신을 위한 키 등을 협상한다.
4. HTTP 요청을 TLS로 보호해 보낸다.
5. 전송 데이터가 IP 패킷과 링크 프레임에 담겨 네트워크를 이동한다.
6. 서버는 데이터를 복원해 요청을 처리하고 응답한다.

HTTP/3는 TCP 대신 UDP 위에서 동작하는 QUIC을 사용하므로 위 과정을 모든 HTTP 통신에 그대로 적용할 수는 없다.

## 6. 실무·면접 핵심 질문

### Q1. IP 주소, MAC 주소, 포트 번호는 어떻게 다른가요?

IP 주소는 네트워크 간 전달에 쓰이는 논리 주소다. MAC 주소는 Ethernet 같은 링크에서 프레임을 전달하는 데 사용한다. 포트 번호는 전송 계층에서 호스트 안의 통신 종단점을 구분한다. MAC 주소가 모든 상황에서 고정되거나 전 세계적으로 유일하다고 가정해서는 안 된다.

### Q2. 스위치와 라우터는 어떻게 다른가요?

일반적인 L2 스위치는 같은 LAN에서 목적지 MAC 주소와 MAC 주소 테이블을 기준으로 프레임을 전달한다. 라우터는 IP 주소와 라우팅 테이블을 기준으로 서로 다른 IP 네트워크 사이에서 패킷을 전달한다. L3 스위치처럼 두 기능을 함께 제공하는 장비도 있다.

### Q3. 계층을 나누면 장애 분석에 어떤 도움이 되나요?

연결 자체가 없으면 케이블·무선 연결부터, 특정 네트워크에 도달하지 못하면 IP 설정과 라우팅을 확인한다. 서비스 연결 실패는 포트·방화벽·서버 리슨 상태 등을, HTTP 오류 응답은 응용 계층을 살펴볼 수 있다. 다만 증상 하나로 원인을 단정해서는 안 된다. 예를 들어 ping 실패는 ICMP 차단 때문일 수도 있어 서버 장애의 충분한 증거가 아니다.

### Q4. OSI와 TCP/IP의 차이는 무엇인가요?

OSI는 통신 기능을 일곱 계층으로 구분하는 참조 모델이고, TCP/IP는 인터넷 프로토콜 구조를 설명한다. TCP/IP 응용 계층은 OSI의 상위 세 계층에 해당하는 기능을 포괄하지만 실제 구현이 정확히 일대일로 대응하는 것은 아니다.

## 7. 발표 핵심 요약

1. OSI는 7계층, TCP/IP는 일반적으로 4계층으로 통신 역할을 구분한다.
2. 데이터는 송신 측에서 캡슐화되고 수신 측에서 역캡슐화된다.
3. IP는 네트워크 간 전달, MAC은 현재 링크의 전달, 포트는 호스트 내 통신 종단점 구분에 사용한다.
