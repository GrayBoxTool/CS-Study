### 🗂️ 자료구조: 최단 경로 알고리즘 / MST (권혜강, 최나현, 김영웅 발표)

*   **왜 알아야 하나**: 5회차 BFS는 "간선 몇 개?"를 셉니다. 지도는 "몇 분?"을 묻습니다. 간선마다 비용이 다르면 먼저 도착한 길이 빠른 길이 아니라서 비용을 보는 도구가 필요합니다.
*   **실생활 연결**: 지도 앱 길찾기(다익스트라, A\*), 인터넷 라우팅(OSPF는 다익스트라, RIP는 벨만-포드), 환율 차익거래 탐지(음수 사이클), 광케이블·전력망 설계(MST).
*   **공통 원리, 완화(relaxation)**: `dist[u] + w < dist[v]`이면 고칩니다. 최단 경로 알고리즘의 차이는 **어떤 순서로, 몇 번 고치느냐**뿐입니다.
*   **Dijkstra**: 아직 확정 안 된 정점 중 가장 가까운 정점을 꺼내 확정합니다. 비용이 0 이상이면 돌아가 봐야 길어지기만 하므로 성립합니다.
    *   우선순위 큐(4회차 Heap)로 최솟값을 꺼내 O(E log V). 배열에서 매번 찾으면 O(V²).
    *   `heapq`엔 값을 줄이는 기능이 없어서 거리가 줄 때마다 새로 넣고, 꺼낸 값이 `dist`보다 크면 낡은 기록이므로 건너뜁니다.
    *   힙 키는 `(거리, 정점)` 순서. 비용이 모두 같으면 BFS와 같습니다. "다익스트라는 비용을 보는 BFS".
*   **Bellman-Ford**: 확정 대신 **모든 간선을 V-1번 완화**합니다. 정점을 반복하지 않는 최단 경로의 간선은 최대 V-1개이기 때문입니다. V번째에도 줄어들면 **출발점에서 도달 가능한 음수 사이클**. O(VE).
*   **Floyd-Warshall**: 모든 쌍의 거리표 `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`. 경유지 k를 하나씩 허용하는 DP라서 **k가 가장 바깥 반복문**이어야 합니다. O(V³), 대각선 `dist[i][i] < 0`이면 음수 사이클.

| 구분 | Dijkstra | Bellman-Ford | Floyd-Warshall |
| :---: | :---: | :---: | :---: |
| 출발점 | 하나 | 하나 | 모든 쌍 |
| 음수 간선 | 불가 (0은 가능) | 가능 | 가능 |
| 음수 사이클 탐지 | 불가 | 가능 (V번째 완화) | 가능 (`dist[i][i] < 0`) |
| 시간 | O(E log V) | O(VE) | O(V³) |
| 고치는 방식 | 가까운 순서로 한 번씩 | 모든 간선을 V-1번 | 경유지를 하나씩 늘리며 |

*   **MST (최소 신장 트리)**: 모든 정점을 사이클 없이 V-1개 간선으로 잇되 **간선 비용 합**이 최소인 트리입니다. 최단 경로는 "이동", MST는 "설치" 비용이라 묻는 질문 자체가 다릅니다. MST 안의 경로가 최단 경로라는 보장도 없습니다.
*   **Kruskal**: 간선을 비용 순으로 정렬해 사이클이 안 생기면 추가합니다. 사이클 판별은 **Union-Find**(`find(u) == find(v)`면 같은 덩어리). O(E log E), 간선이 적은 그래프에 유리.
*   **Prim**: 한 정점에서 시작해 트리에 붙은 간선 중 가장 싼 것을 추가합니다(우선순위 큐). 힙 키는 누적 거리가 아니라 **간선 하나의 비용**입니다. 간선이 빽빽한 그래프에 유리.
*   **왜 "지금 제일 싼 것"만 골라도 될까**: 컷 성질. 그래프를 두 쪽으로 나누면 두 쪽을 잇는 가장 싼 간선은 MST에 넣어도 손해가 없습니다. MST는 음수 간선도 상관없습니다.
*   **앞 회차와 연결**: 2회차 트리(MST가 그 트리), 4회차 Heap(Dijkstra·Prim의 엔진), 5회차 BFS(비용이 같을 때의 Dijkstra), 5회차 사이클 판별(Kruskal은 Union-Find로).

### 🌐 네트워크: DNS 동작 원리 / 브라우저에 URL 입력 시 흐름 (최묘석, 윤형섭, 최승우, 조수연 발표)

*   **DNS**: 도메인 이름을 IP 등 DNS 데이터로 조회하는 **계층형 분산 시스템**입니다. 웹페이지를 가져오는 게 아니라 목적지 주소를 찾아 줍니다.
*   **왜 계층형인가(윤형섭)**: 중앙 서버 하나면 단일 장애점·트래픽 폭주. 영역(Zone)별 권한 위임으로 부하를 나누고, google.com은 자기 권한 네임서버만 고치면 됩니다.
*   **조회 순서**: 브라우저 캐시 → OS 캐시·hosts → (공유기 캐시) → Local DNS(재귀 리졸버) → Root → TLD(.com) → Authoritative. 실제 순서는 OS·브라우저 구현에 따라 다르고, 대부분 캐시 단계에서 끝납니다.
*   **재귀 vs 반복 질의**: 클라이언트 → 재귀 리졸버는 "끝까지 찾아서 최종 답 줘"(재귀), 리졸버 → Root·TLD·권한 서버는 "다음에 물어볼 서버만 알려 줘"(반복). Root·TLD가 상태를 들고 기다리지 않도록 역할을 나눈 것입니다.

| 서버 | 역할 |
| :---: | :--- |
| Root DNS | TLD 네임서버 위치 안내 (논리적으로 13개, Anycast로 전 세계 복제) |
| TLD DNS | 해당 도메인의 권한 네임서버 안내 |
| Authoritative DNS | 실제 레코드 응답 |
| Recursive Resolver | 사용자 대신 조회, 결과 캐싱 |

*   **레코드 & TTL**: A(IPv4), AAAA(IPv6), CNAME(별칭), NS(네임서버), MX(메일), TXT(소유권 인증·SPF). TTL은 캐시 유효 기간입니다. 서버 IP 이전 전에는 TTL을 미리 줄여 두고, 교체 후 다시 늘립니다.
*   **왜 UDP(53)인가**: 요청 1패킷·응답 1패킷이라 3-way handshake가 배보다 배꼽. 신뢰성은 타임아웃 후 재질의로 보완합니다. **TCP 예외**: 응답이 커서 TC(Truncated) 플래그가 오면 TCP로 재요청, 네임서버 간 Zone Transfer(AXFR).
*   **보안**: 평문 DNS는 캐시 포이즈닝·도청에 취약 → DNSSEC(응답 서명), DoT(853), DoH(443).
*   **인프라**: GSLB·CDN은 DNS 응답 단계에서 가까운 데이터센터·엣지 IP를 내려줍니다. 브라우저는 `dns-prefetch`, `preconnect`로 지연을 숨깁니다.
*   **URL 입력부터 화면까지**

| 순서 | 동작 | 연결 회차 |
| :---: | :--- | :---: |
| 1 | URL 파싱, 검색어 판별, HSTS 확인 (Fragment `#`는 서버로 안 보냄) | - |
| 2 | DNS 조회로 IP 확보 | 6회차 |
| 3 | ARP로 게이트웨이 MAC 확인 후 TCP 3-way handshake (HTTP/3면 QUIC) | 1·3회차 |
| 4 | TLS 1.3 핸드셰이크, 인증서 검증, ALPN으로 HTTP 버전 협상 | 4·5회차 |
| 5 | HTTP 요청 → LB → 웹 서버 → WAS → DB → 응답 | 5회차 |
| 6 | HTML → DOM, CSS → CSSOM → Render Tree → Layout → Paint → Composite | 6회차 |

*   **렌더링 포인트(최묘석, 윤형섭)**: `display: none`은 Render Tree에서 빠지고 `visibility: hidden`은 남습니다. CSS는 렌더링 차단, `<script>`는 파서 차단이라 `defer`가 실무 권장입니다. `width·top` 변경은 Layout부터 다시, `transform·opacity`는 Composite만.
*   실제 브라우저는 캐시와 기존 연결을 재사용하고 여러 단계를 병렬로 진행합니다.

### 💬 핵심 질문 정리

*   다익스트라는 왜 음수 간선에서 틀리나? → 꺼낸 정점을 확정하는데, 음수 간선이 있으면 확정 뒤에 더 짧은 길이 생길 수 있습니다. 음수가 있으면 벨만-포드.
*   음수를 없애려고 모든 간선에 같은 값을 더하면? → 경로마다 간선 수가 달라서 순위가 바뀝니다. 안 됩니다.
*   Kruskal과 Prim은 언제 무엇을? → 간선이 적으면 간선 정렬 중심 Kruskal, 빽빽하면 정점 중심 Prim. 연결된 같은 그래프면 총비용은 같습니다.
*   DNS는 왜 UDP를 쓰나, TCP는 언제? → 짧은 단발 질의라 연결 비용을 아낍니다. 응답이 잘리거나(TC) Zone Transfer 때 TCP.
*   재귀와 반복 질의는 왜 나뉘나? → Root·TLD가 전 세계 요청을 대신 끝까지 처리하면 마비됩니다. 이정표만 즉답하고 발품은 리졸버가 뜁니다.
*   (이슈란에서 이어서) 지도 앱은 수백만 교차로에서 어떻게 1초 만에 길을 찾을까? 환율표의 돈이 불어나는 루프는 어떻게 찾을까? 간선 비용이 모두 다르면 MST는 하나뿐일까?
